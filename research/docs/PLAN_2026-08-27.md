### 3.5.1 目标构造：我们的 `rtc_raw` 在结构上是忠实的
```
y_±^(m+1) = y_±^(m) ± h·∇R/(‖∇R‖+ε),   h = η·ρ‖y_0‖ / M_tgt
每步后投影回信赖域球 ‖y−y_0‖ ≤ ρ‖y_0‖;默认 η=1 ⇒ 投影在精确算术下不激活
M_tgt = opa_n_ascent = 2,ρ = 0.10,σ* = 0.278
```
与我们实现一致（σ*/ρ/n_ascent/dual 均对得上）。**RTC 原方案 = 把这里的 `∇_y R` 换成 `JJ^T ∇_y R`。**

### 3.5.2 拟合分支：缺口的真实性质是**优化器动力学**，不是目标几何
```
y_θ^+ = β y_θ + (1−β) y_0,      y_θ^− = (1+β) y_0 − β y_θ
L = ω·mean[(y_θ^+ − ȳ_+)²]/γ_+  +  (1−ω)·mean[(y_θ^− − ȳ_−)²]/γ_−
理想输出空间极小点:  δ_θ* = (a₊d₊ − a₋d₋)/(β(a₊+a₋))  →(局部对称) h̄·u_grad/β
```
论文原文紧接着写：
> "Equation describes the displacement preferred by the loss,
> **while finite fitting may produce a different displacement in the updated model.**"

⇒ **「有限拟合」的缺口 = 一步优化器只走到理想极小点 δ_θ* 的一小部分**，
   而**不是**「目标落在模型可达集之外」。

### 3.5.3 由此得到的方向性重构（**假设，待复现后检验**）
**RTC 把 Gauss-Newton 预条件加错了位置。**
- 原方案：在**目标构造**端，用 `JJ^T g` 替代 `g` 作为目标方向；
- 但按论文自己的记账，损失发生在**拟合**端；
- ⇒ 若要用 `J` 纠正可达性，正确位置是**参数更新那一步**：
  用 Gauss-Newton / 自然梯度步去拟合 `ȳ_+`，而非把目标本身预条件化。

这保留了原 idea 的直觉（用 `J` 处理可达性），但把它放到缺口真正所在处。
它也与今晚的负面结果自洽：ksteps 把目标做得「更可实现」而训练更差（§十四），
正因为目标端本来就不是瓶颈。

**注意这仍只是假设**：需要 (a) 完成官方复现取得同协议对比资格，
(b) 独立测出 δ_θ* 与实际单步位移之比（即真正的 `G_fit`，而非二手转述的 98.7%），
(c) 解决 JVP 数值问题（forward-mode AD），才能实施。**现在不能当结论用。**

## 三·六、Phase 0 读码结果：论文 ↔ 官方代码 ↔ 我们的实现（三方对照）

（02:10–02:30，集群饱和期间完成，零算力。已读官方 `_opa_tr_step` 与 OPA loss block。）

### 目标构造：**三方一致**
官方 `_opa_tr_step` 与论文公式逐行对应，与我们的实现也一致：
```
budget = ρ‖x0‖ ;  step_len = η·budget/n_ascent
每步: x ← x + dir·step_len·g/‖g‖ ,  再投影 d ← d·min(1, budget/‖d‖)
```
`dir_mode` 的四个消融（grad / rand / residual / noop）在官方代码里是**真实分支**，
不是配置换标签 —— 论文的消融声明在代码层面诚实。
✅ 我们的 `rtc_raw` 在构造端是忠实的（σ*=0.278 / ρ=0.10 / n_ascent=2 / dual 全对）。

### 拟合损失：**我们缺少一个核心组件**
官方：
```python
r1 = clamp((adv_clip/adv_clip_max)/2 + 0.5, 0, 1)      # 论文的 ω,来自**组内相对 advantage**
wf_p/wf_n = |y_pos−y_+|.mean()  (detached 自适应归一)
pos_loss = accp·(y_pos−y_+)²/wf_p ;  neg_loss = accm·(y_neg−y_−)²/wf_n
opa_policy = (r1·pos_loss + (1−r1)·neg_loss).mean() · adv_clip_max
```
我们：
```python
_lp = _ap·(_ypos−_ypb)²/_gp ;  _ln = _am·(_yneg−_ymb)²/_gn2      # 双分支/门控/wf 归一 ✅ 一致
_loss_rtc = (0.5·_lp + 0.5·_ln).mean()                            # ❌ ω 固定 0.5
```

**根因（我们代码注释里已写明）**：本仓库 `num_image_per_prompt=1`，
**没有 prompt 组可做组内归一化**，因此结构上无法计算 advantage。

⇒ 由此也解开了先前那个 `48×24` 分组约束的含义：
**`24` 就是 `num_image_per_prompt`，是计算组内相对 advantage 的组大小（类似 GRPO）**，
不是任意的 batch 整形常数。官方 = 48 prompt × 24 图 = 1152 samples/epoch。

### 保真度结论（必须写进论文的限制）
| 组件 | 论文 | 官方代码 | 我们的 `rtc_raw` |
|---|---|---|---|
| 目标构造（ρ/η/n_ascent/投影） | ✅ | ✅ | ✅ 一致 |
| 双分支 v_pos/v_neg（β） | ✅ | ✅ | ✅ 一致 |
| `acc_p/acc_m` 逐样本门控 | ✅ | ✅ | ✅ 一致 |
| `wf` 自适应归一 | ✅ | ✅ | ✅ 一致 |
| **ω（组内 advantage 加权）** | ✅ | ✅ | ❌ **缺失，退化为常数 0.5** |
| `num_image_per_prompt` | 24 | 24 | **1** |
| samples/epoch | 1152 | 1152 | 72 |
| guidance_scale | — | 1.0 | 4.5 |
| margin | 0.005 | 0.005 | **0.0** |
| **行为策略（分支锚 `y_old`）** | EMA 行为策略 | **独立 `"old"` LoRA adapter，训练时现算** | ❌ **用采样时存下的 `rtc_y0` 代替** |
| **分支混合系数 β** | — | **1.0**（sd35_pickscore；open3 用 0.1） | ❌ **0.5** |
| 拟合尺度 `c_adv` | `c_adv·L_OPSD` | `adv_clip_max = 5` | 无对应项（我们直接 `0.5·L_p+0.5·L_n`） |

**行为策略这一项的细节**（补核完成）：
```
官方: transformer.add_adapter("old", ...)           # 独立 LoRA adapter
     set_adapter("old")  → v_old = forward(...)     # 训练时现算,EMA 更新、有意滞后
     v_pos = β·v_θ + (1−β)·v_old
我们: _ypos = β·_yth + (1−β)·_y0b ,  _y0b = sample["rtc_y0"]   # 采样时刻存下的锚
```
因 `y = z_q − σ_q·v` 是仿射映射，`_y0b` 扮演的正是 `y_old`。
但官方的 `v_old` 来自**有意滞后的 EMA adapter**，我们用的是**采样时刻的策略输出**
（1 epoch = 1 优化步下几乎等于当前策略）。
⇒ `v_old ≈ v_θ` 时 `v_pos ≈ v_θ`，**双分支的分离度被削弱，分支结构部分退化**。
这与「ω 缺失」一样，是我们简化版与官方方法的实质差异。

⇒ **`rtc_raw` 作为「与 rtc_kb 只差 precond」的内部受控对比仍然有效**（§十四 的归因不受影响）；
但它**不能被称为 OPSD 的等价实现** —— 缺了 advantage 加权这一核心组件。
今晚测到的拟合缺口 99.59% 是**我们这套简化设置下**的结果，
是否等于 OPSD 原设置下的缺口，必须由官方复现来回答。

## 四、我们手上真正的资产（哪些**不依赖** OPSD 前提，仍然成立）

### 资产 1（强）：teacher 信号有保质期，且远短于训练全程
```
step        teacher−rand（n=24，全部 24/24 同号）      grad−rand
0（初始）   +0.01840  t= +36.1                        +0.0969
61          +0.00706  t= +23.1                        +0.1153
241         −0.00355  t= −11.4                        +0.1020
781         −0.00618  t= −26.2                        +0.0964
```
- 单调衰减，前 61 步（全程 7.6%）就丢掉 62% 的价值，零点在 61~241 之间；
- 跨臂复现：POE-L1.5（多 reward 训练）上 `teacher−rand = −0.0053 (t=−30.8, 24/24)`，
  且其 `rand ≈ 0` ⇒ 排除了「近最优点所以各方向都掉」的解释；
- **直接解释三个冲突消解方法为何全败**（cagrad −7.4% / conflict −5.3% / cconf −5.1%）：
  它们全程用同一套固定权重，而被加权对象的价值在训练早期就变号。
- ⏳ 正在补：`gcraw61/241/781` 在**训练良好**的臂上复测同一曲线（约 01:00 出）。
  这是这条结论最大的弱点——现有轨迹全测在训练失败的 rtckb 上。
- ⚠️ 必须钉住的限制：探针只测 **reward 上升**，不测「保持」。teacher 可能承载的是防退化，
  而 OCR 不可微、无法用这套探针证伪。结论必须限定为「在 reward 上升方向上」。

**落地方式**：teacher 项**调度**（早期强、穿零后退火到 0）vs 固定权重的受控对比。
这是把 observation 变成方法的唯一一步，也是审稿人必问的。

### 资产 2（中）：ksteps 构造在受控对比中全面劣于 raw
n=10 公共步，六轴中五轴显著更差（ocr −0.268 t=−10.3、pick −0.075 t=−8.5、hps −0.028 t=−20.5、

两臂只差 `rtc_precond`，归因干净。
**现在的正确解读**：这是论文「better target can produce a worse finite update」的一个独立实例，
不是我们的新发现——但它是在**另一套训练设置、另一个 reward、另一种构造方式**下复现的，

### 资产 3（中）：gn 方向在本代码库不可靠计算（负面但精确）

须先做最小验证再投入。

### 【21:10 更新】新增一条已确立的结论，Phase 3 排序再调整

**新结论：信赖域 ρ 是装饰性的，且原因可控**（四重证据，详见 OVERNIGHT 同名章节）
```
A 代数  L = mean(r²)/mean|r| 对 r 1-齐次 ⇒ 梯度 0-齐次
B 数值  目标距离放大 100 倍,梯度范数六位小数不变,cos=1.000000
C 实测  ρ 跨 20 倍(0.01/0.03/0.10/0.20,各 n=24),秩和检验两两全不显著
D 因果  γ 跨 ρ 固定为同一常数后,ρ 重新显著(**z=−2.02, p=0.046**, 中位数 2.4 倍) —— 勉强过线,非强证据
```
⇒ **这是目前对 OPSD 最硬的一条批评**：论文围绕信赖域建的投影公式、半径上界、
「bounded target construction」安全性论证，**对更新无一阶影响**；
而唯一真实的步长旋钮 `c_adv=5` 被论文自己承认与 reward 归一化耦合、不能当纯 lr 乘子。

**但它目前不是性能提升**：frozen-const 在 ρ=0.10 的实现增益（0.000172）
**低于** adaptive（0.000212）。价值是把 ρ 变成可调旋钮，而非直接更好。

速率（**已更正**）：稳态 **59.7 秒/epoch**（两点差分：23:48 Epoch 10 → 00:27 Epoch 49），

> ⚠️ 我先前在此处写过「4.95 分钟/epoch、约 67 小时、慢在 `horizon=2`」——**两条都错**。

> 也一并作废——它的实际占用远小于我说的。
> **教训：估长作业耗时必须用两点差分测稳态，不能用累计平均。**
