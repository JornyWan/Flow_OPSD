## ★★★ 最强的一条：**信赖域 ρ 是装饰性的**（15:40，三重证据）

### 证据 A —— 代数：分支损失对残差 1-齐次
官方损失（`train_opsd_ri_sd3.py:1539-1545`）：
```python
with torch.no_grad():
    wf_p = |y_pos − y_plus|.mean(...)          # 归一化器
pos_loss = accp * (y_pos − y_plus)**2 / wf_p
```
记 `r = y_pos − y_plus`，则 `L = mean(r²)/mean|r|` 对 `r` 是 **1-齐次**：`L(cr) = c·L(r)`
⇒ **梯度 0-齐次** ⇒ 对目标距离**完全不敏感**。

### 证据 B —— 数值：复刻其损失结构，把目标位移放大 100 倍
```
目标距离 c:  0.1      0.3      1.0      3.0     10.0
梯度范数:  0.039114 0.039114 0.039114 0.039114 0.039114   ← 六位小数完全相同
cos(与c=1):                          1.000000 1.000000   ← 方向也一致
loss:      0.0039   0.0117   0.0391   0.1173   0.3911    ← loss 随 c 线性(验证 1-齐次)
```
> 对照：**不 detach 归一化器时梯度范数同样恒定**（0.024480）⇒ 与 detach 无关，
> 是损失形式本身的齐次性。（我先前归因于 detach，已更正。）

### 证据 C —— 实测：ρ 跨 **20 倍**，实现增益**无显著变化**（四点，各 n=24）
```
ρ      中位数      均值      均值/中位数   G_construct@ρ
0.01   0.000150   0.000204     1.36        0.01924
0.03   0.000234   0.000388     1.66        0.03682
0.10   0.000212   0.000202     0.96        0.04975
0.20   0.000222   0.000211     0.95        0.03951

Mann-Whitney 秩和检验(两两)：
  0.01 vs 0.10  z=−0.82    0.03 vs 0.10  z=+0.99
  0.20 vs 0.10  z=+0.16    0.01 vs 0.20  z=−0.33      ← 全部不显著
```
**ρ 跨 20 倍，实现增益两两比较全部不显著；同期构造增益变化 2.6 倍。**

训练侧同样重合（12 epoch）：ρ=0.01 → +0.0585；ρ=0.10 → +0.0598。

> **统计方法的更正**：我最初用**均值 + 3σ 粗判**。但分布明显**右偏**（均值/中位数最高 1.66，
> ρ=0.03 的最大值是其中位数的 6 倍），均值不是合适的统计量 ——
> 它一度让 ρ=0.03 看起来是别处的 2 倍（0.000388 vs 0.000202）。
> 改用**中位数 + 秩和检验**后，四点两两比较全部不显著，结论反而更强、更稳。

### 证据 D —— **因果验证**：去掉齐次性后 ρ 重新生效
把归一化器 γ **跨 ρ 固定为同一常数**（5.4885e-2），其余不变：
```
                  ρ=0.01      ρ=0.10     秩和检验
adaptive        0.000150    0.000212    z=−0.82   不显著 → ρ 无效
frozen-const    0.000071    0.000172    z=−2.02   **勉强显著(p=0.046) → ρ 重新生效**
dy_norm(frozen)   0.1445      0.2183              ← 位移幅度也随 ρ 变化
```
⇒ **ρ 的失效是齐次性造成的，且是可逆的** —— 这把「批评」升级为「可控的设计缺陷」。

> ⚠️ **但这不是立刻能赢的改动**：frozen-const 在 ρ=0.10 处的实现增益（0.000172）
> **低于** adaptive（0.000212）。价值在于**让 ρ 成为真正可调的旋钮**（目前调它毫无意义），
> 而非直接提升。下一步应在 frozen-const 下**向大 ρ 扫描**（0.3 / 1.0），
> 看实现增益能否继续上升 —— 那才是把机制理解转成性能的地方。

> **实验设计的一次自我纠正**：第一版把 γ 冻结在**各自 run 的首个 batch**，
> 而该值本身正比于该 run 的 ρ（实测 5.4885e-3 vs 5.4885e-2，正好差 10 倍），
> 于是 `2r/γ` 中分子分母同比例缩放，**尺度不变性根本没被去掉**，
> 得到 z=−0.16 的**假阴性**。是「先确认被改的量在各条件下确实不同」这一步拦下的。

### 结论
论文围绕信赖域建立了完整论证：投影公式 Eq.(target_projection)、半径上界
`‖y±−y_0‖ ≤ ρ‖y_0‖`、以及「bounded target construction」的安全性。
**但 ρ 对参数更新没有一阶影响，对训练也没有可测量的影响。**
唯一真正的步长旋钮是 `c_adv = adv_clip_max = 5`，而论文自己承认它
*"is shared by reward normalization and branch-loss scaling … rather than acting as a pure
learning-rate multiplier"* —— **无法独立调节**。
⇒ **方法的「可控性」论证与实际可控量之间存在错配。**

> **适用范围**：证据 A/B 直接针对官方代码与损失形式；
> 证据 C 目前在我们的实现里测（归一化器结构与官方一致，但 β=0.5 vs 官方 1.0）。
> 注意 **β=1.0 时 `y_pos = y_θ`，`r ≈ −c·d` 是纯缩放，齐次性论证反而更严格**。
> 要写进论文，证据 C 应在官方代码补测（ρ 扫描剩余点 + 官方侧重测）。

### 这同时证实与推翻了两件事
- ✅ **实质成立**：「构造增益几乎全部丢在有限拟合」——我们独立测到 **99.59%**，

1. **目标构造是好的** —— `acc_p=97.6%`，构造增益 0.0498；
2. **拟合只实现了 0.41%**；
3. **实现的位移方向与 reward 梯度几乎不相关** —— `cos ≈ 4.1e-4`，

> ⚠️ 口径限制：`rtc_realized_cos` 是**带符号余弦的均值**，`1/√d` 是随机方向的**期望绝对值**，
> 两者不完全同口径。但该值在 12 个 epoch 上稳定为正（se 4.8e-5），
> 说明是真实的小幅正对齐，而非正负抵消的噪声。

### 对方向的影响（与 PLAN §三·五 的重构互相印证）
既然目标端已经很好（97.6% 采纳率），而拟合端丢掉 99.6%，
**RTC 把 Gauss-Newton 预条件加在「目标构造」上就是加错了位置**；
正确的位置是**参数更新那一步**——用 GN/自然梯度步去拟合 `ȳ_+`。
这也解释了 §十四 的负面结果：ksteps 把目标做得更「可实现」而训练更差，
因为**目标端本来就不是瓶颈**。

## TL;DR

### ✅ 四个成立的结果（可写论文）

1. **teacher 子空间存在可量化的天花板 ~15%**（n=24 配对，t=106.7）：
   低噪声点上 reward 梯度方向可构造 +0.0928 增益，teacher 方向只有 +0.0143。
   n=8 多方向确认：teacher / 投影 / 等权组合 / 按实测选的最优组合**全部落在 0.009–0.018**。
   > 独立解释了 conflict-averse 系列（cagrad −7.4% / conflict −5.3% / cconf −5.1%）
   > 为何**全部**有害——都在同一天花板下腾挪；`gc_pick_sum` 仅 5.6–9.7%
   > ⇒ 等权组合几乎从不是正确答案。
2. **RTC-K 的目标构造突破该天花板**：严格半径匹配下 **2.34× teacher（t=+51.5）**。
3. **可实现方向的改善"不耐传播"**：即时 reward 上 ksteps 在 r=0.10 达 grad 的 58.8%，
   但**固定后缀 F_q 上只有 27–31%** —— 改善在剩余去噪步中大量流失。
   OPSD 的固定后缀界只给 Lipschitz 上界，未区分方向间的传播差异。

4. **★ teacher 方向的价值随训练耗尽并反转**（跨两个 checkpoint 复现，n=8 各）：
   把 `G_construct` 探针指向**已训练**的 checkpoint 复测（此前所有测量都只在初始学生上做）。
   ```
   checkpoint                        grad−rand               teacher−rand
   初始学生（未训练）         +0.0969 t= +85.6 24/24   +0.0184 t=+36.1 24/24
   rtckb-781（单 reward）     +0.0964 t=+111.2 24/24   −0.0062 t=−26.2 24/24
   POE-L1.5-781（多 reward）  +0.0938 t=+124.3 24/24   −0.0053 t=−30.8 24/24
   ```
   **梯度方向相对随机的优势不随训练变化（三点均 +0.095）；teacher 方向的优势变负。**
   > 关键混淆已证伪：POE-L1.5 是**多 reward** 训练（PickScore+OCR+GenEval），
   > 其 `gc_G_rand = +0.0011`（≈0，而非 rtckb 的 −0.0117）⇒ 它**不在被测 reward 的最优点附近**，
   > 因此"近最优点所以各方向都掉"解释不成立。结论跨臂、跨训练目标。
   >
   > 这比第 1 条的"初始化天花板"强得多：不只是 teacher 子空间容量有限，
   > 而是**它承载的上升信息会在训练中被耗尽**。三个冲突消解方法（cagrad/conflict/cconf）
   > 因此注定失败——它们重新加权的子空间在工作点上已不含上升方向。

### ⚠️ 现象已测量，机制**未解决**（已按事先写定的停止规则停止投入）

**可如实写下的**：拟合一个由参数位移 `Δθ` 产生的目标，得到的更新方向与 `Δθ`
**只保留极小的分量**——`cos ≈ 0.013`，是随机基准 `1/√d ≈ 2.2e-4`（LoRA ~2×10⁷ 维）的
**约 60 倍**，即并非无关，但绝大部分更新去了别处。

**未解决的**：偶发负 cos（2/8）在 `−grad = J^T J Δθ` 下不该出现，说明该关系并不完整描述实际计算。
三次测量错误（假设 `y_θ=y_0`／比错 `Δθ` 步数／读跨 batch 累积梯度）后设停止规则并触发，停止投入。

**已排除的两个假说**（均按事先判据）：
- `J^T J` 病态导致方向丢失 → 被负 cos 证伪；
- 批内目标冲突（`kbest` 逐样本选点）→ 固定 K=2 全批共用 `Δθ` 后 cos 仍 ≈0（t=1.57）。

**日后若续查的建议**：不测 cos，改测"拟合 N 步后的 `y_θ`"与"`y_{θ+Δθ}`"的距离随 N 的变化——
绕开梯度累积、双分支、门控等全部干扰项。

**三个要点**

- **rand 显著为负（t≈−15）是整个诊断可信的前提**：该半径下随机移动确实损害质量，

  cos≈0.003 说明的是**端点式目标**与 reward 梯度正交，**不是 teacher 没有信号**。
  被指控的对象是端点目标，不是 teacher。
- **grad 是 teacher 的 6.48×** ⇒ 现有 OPD 只拿到低噪声可构造增益的 15.4%，
  剩余 85% 是结构性拿不到的空间。我们的 +0.0928 也是 OPSD 自报 G_construct=+0.03511 的 **2.6×**。

先前 n=3 给出 17.1%，n=24 给出 15.4%，一致。单 seed，论文里需再扩多 seed。

## 二、RTC 原始形式：为什么撤回

理论本身复核无误（Cauchy-Schwarz 给出实现增益倍数 = 1/cos(Ag,g) ≥ 1）。
失败在**数值实现**，而我按判据逐条排查后撤回了结论：

| 我先前的说法 | 实际 | 处置 |
|---|---|---|
| cos(JJ^T g,g)=0.0153 ⇒ 65× 提升 | eps_stab=0.34（应≈1）⇒ 噪声主导 | **撤回** |
| "fp16 autocast 导致舍入噪声" | `autocast` 实为 `nullcontext`，前向本就是 fp32；真实低精度源是 **TF32**（尾数 10 位） | **更正** |
| "bf16 量化把 0.1% 扰动抹掉" | 同一次运行的 eps 扫描 scale=1 却报 dv=1.09 | **同样不成立** |

已排除的可能：前向不确定性（实测 max\|vA−vB\|=0，无 dropout）、
拷贝未落地（期望改动=实际落地=2.28）、参数不在前向路径（1000× 扰动 dv=5.45）。
**"扰动生效"与"扰动无效"两个测量在同一次运行内互相矛盾，真因未查明——如实记录，不掩饰。**
精确双反向 JVP 亦不可用（flash-attn 无二阶导）。

**决定**：停止追查有限差分，因为它已被替换掉，继续 debug 是在为不再使用的路径消耗 H200。

## 三、RTC-K：先失败，后定位，已修复（今晚最重要的一段）

### 3.1 初次实测：acc_p=0.31，低于随机

### 3.4 我基于 n=1 得出的两条结论是错的，已更正

| 先前说法（n=1） | n=12 实测 |
|---|---|
| "ρ=0.10 对可实现方向过大，dR 翻负（−0.0037，win 0.361）" | **+0.03153±0.00268，win 0.851，约 12σ 显著为正** |
| "上升路径是弯的，线性化丢掉 3.3×" | **反了**：沿最优迭代点方向外推到 0.10 得 +0.0315，比停在最优迭代点的 +0.0168 好 **1.9×** |

**真因不是噪声，而是两次测的是不同方向**：旧那次 `_dir` 指向 **K=4 终点**（已越过极值的坏方向），
新那次因 `rtc_kbest` 默认开启，`_dir` 指向**最优迭代点**（好方向）。

> **正确表述**：关键在于**用路径上的哪个点定义方向**，而非"路径弯曲本身携带增益"。
> 方向选对后，沿它线性外推反而更好。

**连带后果**：我加的"信赖域上限"（`budget = min(budget, |dir|)`）**是次优的** ——
它把位移停在 ~5%，而外推到 10% 能多拿 ~1.9×。已改为可配置 `rtc_kcap`，
`smk_nocap`(1034432) 实测验证中；`rtckb` 约 05:53 启动前来得及改。

### 3.5 三处修复（都是真 bug，不是调参）

1. **按实测 reward 逐样本取最优迭代点**，而非固定 K。自适应、免调参，
   且与 OPSD"用实测而非一阶预测做接受判定"的哲学一致。
2. **信赖域必须是上限而非强制值**：原构造式 `y_p = y0 + budget·dir/|dir|`
   会把位移**强行拉伸**到 ρ|y0|=10% —— 正是曲线上翻负的那个半径。
   改为 `budget = min(budget, |dir|)`。即使取到最优迭代点，旧代码也会把它重新推过头。
3. **`continue` 绕过 `global_step`**（详见第五节）。

## 四、新方向 RTP（定位在追查中被修正，变得更好）

### 4.1 最初的想法

teacher 输出本身就是"另一组 LoRA 权重下的模型输出"，**天然落在可达集内**；
而探针已证明 teacher 方向 reward 显著为正（t=36.1）。
所以：在 span{y_Ti − y_0} 内对 reward 梯度做最小二乘投影，得到
**可实现 + reward 对齐**的方向。

### 4.2 代码正确性：CPU 单元测试五项判据全过

```
残差与子空间正交    max|Dᵀ(g−p)| = 3.8e-05   ← 确实是投影（定义性判据）
|p| ≤ |g|                              True
cos(投影,g)=0.0575  ≥ 各列最大 0.0202   True   ← 优于任一单独 teacher
cos(等权和,g)=−0.0089 ≤ 投影            True   ← 优于等权组合
半径匹配                              精确
```

### 4.3 两次门控白测，以及由此得到的定位修正

第一次（1034417）：`gc_ntproj = 1` —— 投影子空间退化成一维，tproj ≡ teacher 方向。
根因在 `train_sd3_opd.py:726`：**"每个 slot 计算全部 teacher 目标"只在 `cagrad`/`ste` 开启时执行**，
否则 **OPD 每个 batch 只用一个 teacher**（按数据集轮转）。

第二次（1034423）：修好了代码，但计算节点读到**过期的 config**（`K_max=1`）。
预检的两道关卡各查一半，正好漏掉"配置早已存在、本次只改内容"这种情况。
已新增 `RUN_REQUIRE_CFG_MARKER`。第三次（1034424）确认 `K_max=3`，门控终于有效。

**定位修正（往好的方向）**：既然 baseline 每个 batch 只用一个 teacher，
**RTP 的对手就不是"等权求和"，而是你们自己做过的 conflict-averse 组合**
（cagrad −7.4% / conflict −5.3% / cconf −5.1%，三个全部有害）。

> RTP 用同一套机制（每状态算全部 teacher），但把组合规则从
> **基于梯度冲突的启发式** 换成 **由实测 reward 梯度决定的最优组合**。
> 叙事因此更干净：**在已经证明"冲突消解"行不通的地方，给出一个有依据的组合规则。**

**门控判据**（预先定死，不事后挪动）：`G_tproj` 必须显著 > `G_teacher`。未通过则不投入训练。

### 4.4 那两次白测仍提供了有效的交叉验证

- `gc_G_grad ≈ 0.094` 与独立的 n=24 测量 0.0928 吻合 ✓
- `gc_G_ksteps` 在 ρ=0.10 处为**负**（−0.0028），独立印证 kcurve 的
  "该半径对可实现方向过大" ✓

## 五、一个会静默毁掉整次训练的 bug（已修）

RTC 训练分支末尾的 `continue` 位于 `with accelerator.accumulate(...)` **内部**，
而 `info` 的汇总/上报块是 `for j` 循环体内、`with` 之外的**兄弟语句** —— continue 把它整个跳过。

三个后果，**都不会让程序崩溃**，所以从"没崩"完全看不出来：

| 后果 | 说明 |
|---|---|
| 训练指标丢失 | `rtc_loss`/`grad_norm` 从不上报（实测确实全部缺失，这才发现的） |
| **checkpoint 互相覆盖** | 路径是 `checkpoint-{global_step}`，而 global_step 恒为 0 ⇒ 800 epoch 跑完**只剩一个点，没有轨迹可评测** |
| EMA 节奏错乱 | `ema.step(..., 0)`，`update_step_interval=8` 的判据恒成立 |
| **诊断样本量塌成 n=1** | diag2 用 `wandb.log(..., step=global_step)`，step 恒为 0 ⇒ 每个 epoch 的诊断互相覆盖 |

特别危险的地方：`save_ckpt` 的触发条件是 `epoch % save_freq`（不是 global_step），
所以**保存照常在发生**，只是全部写进同一个路径。

已在 continue 之前补上同样的 sync_gradients 汇总块。

可辩护的表述是"两臂各自处在其最优半径附近的对比"。报告时须同时给出实际有效半径与 reward-位移曲线。

### 这不是矛盾——是我先前挑错了比较基准

`rtcraw` 对照臂用的是 **grad 方向**，而探针测得：

| 目标 | G_construct | 说明 |
|---|---|---|

这让负面结果从"不可解释"变成**完全自洽**——探针与训练结果指向同一件事。

### 对 idea 的影响（如果在完整数据集上成立）

- **核心主张不成立**：用可实现方向替换 reward 梯度方向，并不能提高训练效果；
- **仍可保留的正向结果**：teacher 子空间天花板 ~15%（n=24/n=8 多重配对）、

## 十三、★ teacher 方向价值随训练反转（今晚最强的新结果）

### 动机
此前所有 `G_construct` 测量都在**初始学生**（新建 LoRA）上做。
若"teacher 子空间天花板"只在初始化成立，它就是初始化伪影，论文里站不住。

### 做法

### 结果（每 epoch 内配对）

  ⇒ **投影带来的优势不跨臂稳健，不能当作结论写。**

  > 能否直接证伪？**部分不能**：探针只支持 `pickscore` / `aesthetic` 两个可微 reward，
  > 而真正崩掉的 OCR **不可微**，无法用这套探针测；
  > aesthetic 在 rtckb 训练中反而上升（5.98→6.13），拿它做对照说服力有限。
  > ⇒ 论文里必须把结论**限定为"在 reward 上升方向上"**，不能写成"teacher 无用"。

不像 rtckb 那样几乎不变。准确说法是「**teacher 变号，而 grad 全程保持强正且量级高一个数量级**」，
**不能说 grad 完全不衰减**。

### 论文可写的形式
"多 teacher 蒸馏信号有保质期，且远短于训练全程。"
⇒ 直接解释固定权重方案（cagrad/conflict/cconf）为何全败：
**它们在整个训练过程用同一套权重，而被加权对象的价值在训练早期就变号。**
⇒ 可操作设计：teacher 项应被**调度**（早期强、穿零后退火到 0），而非固定。

  > 数值核对：pickscore = `logit_scale × cos / 26`，logit_scale≈100 ⇒ 理论范围约 ±3.85，
  > **并非以 1.0 为上界** ⇒ >1 是合法取值，不是 bug（全库 175 条中仅 rtcraw 的若干条越过 1.0）。
- **OCR**：⚠️ **更正早先说法**。rtcraw 的 OCR 也在退化（0.438 → 0.198），
  只是退化**显著更轻**、起点更高，781 步时仍是 rtckb 的 5.2 倍。
  准确表述是「ksteps 构造使 OCR 退化大幅加剧」，**不能写成「raw 不退化」**。

### ⚠️ 一个被抓住的选择效应
n=3（步 61/151/241）时 geneval 是 **3/3 同号、mean −0.0677**；
加入步 331 后该点符号翻转（+0.0391）⇒ 变成 3/4、t=−1.21 **不显著**；
n=6 时仍为 5/6、t=−1.63 不显著；**但 n=10 时变为 9/10、t=−3.53 显著**。
⇒ 同一条结论在 n=3「显著」、n=4/6「不显著」、n=10「显著」之间摆动。
**教训不是「小样本会出错」，而是「中途的显著性判断只能当方向，定稿必须用预先约定的完整 step 集」。**
公共 step 集扩大一个点就足以推翻一条"看起来一致"的结论。
当时按自定规则（n<10 只报方向）未报数值，恰好避免了错误结论。

## 十五、主方法 gn：从未被训练 → 经四轮定位判定为**不可靠计算**

计划中的主方法是 `rtc_gn`（Gauss-Newton 预条件 JJ^T g），但核查发现：
- 所有 800-epoch 训练臂的 `rtc_precond` 都是 `'ksteps'` 或 `'raw'`；
- `rtc_gn`/`rtc_gn_nodual` 只存在于 `epochs=100000` 的探针配置，**没有训练版**；
- `logs/` 下没有任何 GN 目录。

⇒ **§十四 的负面结果针对的是 ksteps 变体，不能外推到 gn。**

gn 代码路径本身已验证可用（不是只看 exit=0）：
`smk_rtcgn_1034405/1034407` 产出 `rtc_cos_gn_g=0.0154/0.0162`（非零且小 ⇒ g 大部分落在
不可实现子空间，正是收益前提）、`acc_p=0.72/0.86`、`acc_m=0.97/0.94`、0 错误行。

⚠️ **保留意见**：gn 方向靠有限差分估 JVP，其数值有效性今晚**未被证实**

**不能说它就是真的 JJ^T g**。这一条必须在论文里如实写明。

### 15.1 早期校验：启动 15 分钟即判定不通过（避免白烧 7 小时 H200）
```
rtc_cos_gn_g = 0.0000   ← 判据核心
rtc_dirnorm  = 0.0000   ← 方向是零向量
rtc_acc_p/m  = 1.0000   ← 零向量下"采纳"是平凡的，**不能当作通过**
```
决定性诊断：`|h*u| = 9.57e-02`（≈|p| 的 0.1%，并非微小量），而 `max|v1−v0| = 0.000000e+00`。
舍入会给微小非零值，**恰好 0 说明扰动没进到前向**。
> 若只看 exit code，这个运行会被判为"正常训练中"。这正是"不能只看 exit=0"的实例。

### 15.2 四轮定位，每轮修到真因，每轮暴露更深一层
| 轮次 | 做法 | 结果 |
|---|---|---|
| 1 | 默认 FD（`rtc_fd_fp32=True`） | `max\|v1−v0\|` **恒为 0**。真因：**我今晚为解决 FD 舍入噪声而加的 `_fp32_fd()`** 关掉了 TF32 |
| 2 | 强制 SDPA **math 后端** | flash-attn 二阶导限制**解除**（旧错误消失），但 **OOM**（140GB 卡上已分配 136.6 GiB） |
| 3 | 双反向**按样本分块** | OOM 解决、0 报错，但方向 **nan** |
| 4 | `_w` 由全零改小随机（`J^T w` 对 `w` 线性 ⇒ 数学等价，只避开退化点） | `s2` 由 0 变 1.093（退化点消除），`dir_ex` **仍 nan** |

最终定位（`[JVP-DBG]` 实测，非猜测）：
```
vt2: finite=True fp32 absmax=6.412    yt2: finite=True fp32 absmax=4.351
jtw: n=382 none=0 nonfinite=0         s2:  finite=True absmax=1.093
dir_ex: finite=False  nan
```
**前向有限、`J^T w` 全部 382 项有限、`s2` 有限，唯独 `grad(s2, w)` 产出 nan**
⇒ nan 出在**二次求导本身**，不是输入退化、不是上游溢出。

### 15.3 结论（如实写）
`JJ^T g` 在当前代码库/精度下**没有可靠的计算方式**：
- 精确 JVP：flash-attn 无二阶导；换 math 后端可跑但产出 nan；
- 有限差分：fp32/关 TF32 下恒为 0；fp16/TF32 下被舍入噪声主导（稳定性 cos=0.34，本该 ~1）。

**因此 rtc_gn 臂今晚无法运行。这不是"没排上队"，是方法的实现前提不成立。**
§十四 的负面结果只针对 ksteps 变体，**不能外推到 gn**——gn 既未被证实也未被证伪。

### 15.4 建议的下一步（未实施）
用 **forward-mode AD**（`torch.func.jvp` + `functional_call`）直接算 JVP——
这本就是算 `J u` 的正确工具，完全绕开 double-backward 及其数值问题。
代价：需把 transformer 改成函数式调用，改动较大，不宜深夜未验证地写。
风险：flash-attn 可能同样缺 forward-mode 规则，须先做最小验证再投入。
