# 0051 预注册:Gate P = LSR-OPSD 的零训练 oracle 探针(2026-08-31 12:05,launch 前写定)

来源:Codex 0050 §4 推荐的 **LSR-OPSD**(Local Specialist-Retention Target Portfolio)。
Gate P 是它的**前置闸门** —— 不训练,只在冻结 state 上问一句:
**official 的聚合方向,相对一个小方向组合,是否真的留下了局部 Pareto headroom?**
**Gate P 不过就不训练**,避免再花 5 GPU-小时换一个"打平"。

## ① 候选方向组合(七个,半径完全一致)

在同一个 on-policy 锚点 `y0` 上:

| 记号 | kind | 含义 |
|---|---|---|
| `u0_official` | open3 | 官方聚合方向(= 训练实际用的 `y_plus`) |
| `u_pickscore` / `u_clipscore` / `u_hpsv2` | 单轴 | 各轴自己的上升方向 |
| `u_pick+clip` / `u_pick+hpsv` / `u_clip+hpsv` | mixed | 两两之和 |

**七个候选都走官方同一个 `_opa_tr_step`**(同 `rho` / `n_ascent` / `eta` / trust ball),
所以彼此**只差方向、半径相同** —— 差值可直接归因于方向,不掺步长。
每个候选目标 `y_j` 都用 open3 精确前向打三轴分,得 `ΔR_{j,k}=R_k(y_j)−R_k(y0)`。

## ② 选择规则(LSR)

**不除以 raw `R_k(y0)`**(那会把三轴的单位混在一起,正是 N1 栽的地方),
改用每轴自己的**局部 headroom**:

    H_k = max_j ΔR_{j,k}
    retention_{j,k} = ΔR_{j,k} / (H_k + eps)
    j* = argmax_j  min_k retention_{j,k}          # max-min,保住最弱轴

## ③ 判据(**先写后测**;Codex 0050 §4.4 建议值,本次采纳为正式阈值)

| # | 判据 | 阈值 |
|---|---|---|
| P1 | 选中非 `u0` 的 state 占比 | **≥ 20%** |
| P2 | median worst-axis retention 相对 `u0` 的提升(**仅在选择改变的 state 上算**,见修订) | **≥ 15%** |
| P3 | mean scalar Open3 target gain 相对 `u0` 的下降 | **≤ 5%** |
| P4 | 三轴中出现负 gain 的比率 | **不高于 `u0`** |
| P5 | 换 seed 复跑后的选择稳定率 | **≥ 70%** |

### P2 的修订(2026-08-31 12:20,**在任何真实数据产出之前**)

写分析脚本的合成自检时发现:**P2 按原文"对全体取 median"是有假阴性缺陷的判据。**

max-min 规则下,凡 `u0` 已是 argmax 的 state,`retention_LSR` 与 `retention_u0` **逐位相同**,
差值恒为 0。于是只要多数 state 选中 `u0`(而 P1 阈值本身只要求 ≥20% 改选,
即允许多达 80% 不改选),**中位数就被钉死在 0**。

合成自检实测:构造成"LSR 明明救回 40/100 条最弱轴"的数据,
原判据仍读作 **P2 = +0.00%**,闸门误判为"不过"。

**⇒ P2 改为只在"选择真的改变了的 state"上算**(整体效应由 `P1 × 条件提升` 表达),
并另报全体平均提升作信息项。修正后同一份合成数据得 **P2 = +500%(0.30 vs 0.05)**,与手算一致。

**这是修一个坏掉的判据,不是看到结果后挪门槛 —— 修订发生在探针尚未产出任何数据之时。**

**P1–P4 由本次探针直接判;P5 需要第二次探针(换 `RPI_SEED`),
仅在 P1–P4 全过时才跑** —— 不先花那份算力。

**全部通过才写 LSR 的训练臂。任一条不过,记为"official 方向已无局部 headroom",
LSR 线终止,不做"调阈值再看一遍"。**

## ③a ★ 升级为 v2:候选方向改在 **rollout 终点**打分(2026-08-31 18:10,**v1 从未运行过**)

0055 用实测确立 **H1**:构造目标的 rollout 可达率**内在地**随训练下降
(98.73% → 95.49% → 87.67%;门控版 100 updates 时 52%。降幅之比 0.93、趋势 p=0.0000)。

⇒ **clean 目标上的 ΔR 与"最终图是否更好"在训练后期严重脱钩**,
而 v1 恰恰用 clean 层 ΔR 给候选打分 —— **测的是弱代理量**。

**v2 的改动(唯一一处)**:每个候选目标 `y_j` 先经
`_dpm2_continue_from(zq, kq, y_j, prev_x0, …)` 走完剩余扩散,在**最终图**上打三轴分。
选择规则(局部 headroom 归一 + max-min)与 P1–P4 阈值**全部不变**。

**同时保留 clean 层分数**(只多一次已有的打分),每个 state 都能直接量化
"clean 说更好"与"rollout 也更好"的脱钩程度 ⇒ **v2 严格比 v1 信息量大**。

**已 hold 的 4 个副本从未运行过 v1**,所以这不是"改正在跑的实验",
而是在**任何 v1 数据产生之前**换成对齐的判据。
§③b 记录的"必要不充分"限制,**因此对 v2 不再适用**(保留原文以存推理链)。

## ③b ⚠️ 限制:Gate P **v1** 是必要不充分的(2026-08-31 14:20 写,**已被 §③a 解决**)

0053 实测:官方 OPSD 的 **rollout 认证率**从 0.95 单调掉到 **0.52**(100 updates),
而**构造层**的 ΔR 几乎总为正(98.6%)。
⇒ **clean 目标上的 ΔR,与"最终采样图是否更好"之间的关联在训练后期很弱。**

Gate P 恰恰是用 clean 目标上的 ΔR 给候选方向打分。因此:

> **即便 P1–P4 全过,也只证明"构造层存在局部 Pareto headroom",
> 不能推出 LSR 训练臂会赢** —— 选出的目标可能同样不可达。

**本次不改 Gate P**(构造层有没有 headroom 仍是个真问题,且它已排队),
但**解读时不得把"Gate P 通过"等同于"LSR 会成功"**。
更对齐的设计是 Gate P v2:候选方向改在 **rollout 终点**(`_dpm2_continue_from`)上打分。

## ③c ⚠️ 负面先验:同类操作(best-of-N 选目标)已有一次实测判负(2026-08-31 22:55)

`opsd_topk100_sd35_pickscore`(`opa_topk=6`,best-of-N 选目标)的 held-out:

    Pick*(训练目标) −11.80×2σ (t=−6.18)   更差
    HPSv2.1          −8.00×2σ (t=−4.37)   更差
    ImgR             −5.63×2σ (t=−2.94)   更差
    ⇒ 0 胜 3 负

**Gate P/LSR 的核心动作正是"从候选池里按准则挑一个目标",与 topk 同类。**

⇒ **下调本闸门的先验。** LSR 仍值得测(v2 改在 rollout 层打分,
选择准则也不同 —— max-min 局部 headroom vs 单纯选 reward 最高),
**但"选更好的目标"这个动作本身已有一次负面实测,不能当作显然有益。**

**caveat**:该 topk 跑在旧仓库、不同种子、且 `opa_topk` 是我们自己加的扩展(非官方);
但效应量大(t 到 −6.18),种子方差不太可能是全部解释。

## ④ 预写失败模式(防止事后找补)

- **(a) P1 不过(几乎总选 u0)**:说明官方聚合方向在局部已近最优 ⇒
  LSR 与 A1 会是同一类失败(干预极少发生)。**此时应终止 LSR,不是加候选。**
- **(b) P1 过但 P2 不过**:换了方向但最弱轴没多拿到 ⇒ max-min 规则无效,
  问题不在"选哪个方向"而在"候选集本身不含更好的方向"。
- **(c) P2 过但 P3 不过**:靠牺牲总量换均衡 ⇒ 这是又一次沿 Pareto 滑动(N1 已判负),不算改善。
- **(d) 全过**:才有资格排 LSR 训练臂,并按 0041 的口径做配对 A/B。
