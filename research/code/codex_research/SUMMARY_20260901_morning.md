## ① 今晚新增的结论

### 1. Q2c:同 prompt 梯度相干性 **7.8×**(§4.81)—— 第一个通过全部纪律的结构性正结果

| | 值 |
|---|---|
| 同 prompt 平均余弦(n=140 对) | **+0.01300** |
| 跨 prompt 平均余弦(n=3985 对) | **+0.00166** |
| 置换检验(2 万次) | **p = 0.0000** |
| 配对法(记录内同 vs 跨) | t = **+4.28**,69% 记录为正 |
| 随 n 稳定性(**新采的 epoch 3–5**) | +0.0031 → **+0.0239**,单调增大 |

⚠️ **n=46 对时我差点写反。** 当时脚本按"均值比 >3 即显著"打出"显著更相干"(5.20×),
补检验后 t=+1.00、置换 p=0.3796 —— **是噪声**。压住不写、继续攒到 n=140 才成立。
教训:**比值不是显著性**。已写进记忆 [[small-n-significance-flips]]。

### 2. 由此得到的方差分解(§4.81)

`g_i = G + p_c + ξ_i`,以 `E‖g‖²=1` 为单位:

- 全局信号 `‖G‖²` = **0.00166**
- **prompt 专属分量 `E‖p‖²` = 0.01134 —— 是全局信号的 6.8 倍**
- 逐样本残差 `E‖ξ‖²` = 0.9870

⇒ 当前批(48 prompt × 24 图 = 1152)的能量构成:**信号 60.3% / prompt 噪声 8.6% / 样本噪声 31.1%**。

| 配置 | B | 信号% |
|---|---|---|
| **当前 48×24** | 1152 | **60.3%** |
| 1152×1(同算力极限) | 1152 | 65.7% |
| 48×96(4× 算力) | 4608 | 78.7% |
| **192×24(4× 算力)** | 4608 | **85.9%** |

**同算力重组批构成的天花板只有 +9%(相对)** ⇒ 不值得单独做臂(先量天花板再动手)。
4× 算力时**加 prompt 明显优于加图**。

### 3. 两条方向被**结构性**关闭(不是经验性,是原理上)

- **梯度相干分批** = 恒等变换。梯度累积是线性的,整批梯度与样本如何切分成 microbatch **无关**;
  按 prompt 分组后 `optimizer.step()` 看到的梯度一个 bit 都不变。**永久关闭,不需再实验。**
- **"减每 prompt 图数换更多 update"** 不干净(§4.83)。查实
  `num_image_per_prompt=24` **一物两用**:除梯度平均外还喂
  `PerPromptStatTracker` 的组内优势归一化,而 **OPSD 损失确实用它**
  (`L1851 adv → L1881 r1 → L1996 opa_policy`)。减到 3 会让优势由 3 样本估计,训练行为实质改变。

### 4. Gate B 上线:换仪器测临界批量(§4.82,预注册 0064)

**先纠正 §4.78 的一个方法学问题**:那里由 ρ 的**点估计**推出"4× batch 有用"。
按记录聚类重估(同记录内 15 个余弦共享样本、不独立):
ρ=+0.00120,**t=+2.46 未过 |t|>2.5**,`B_noise` 的 95%CI **[464, 4131]**
—— **把 B_eff=1152 夹在正中间,判不了**。

改用**半批(McCandlish)估计量**:`B_noise = B·(‖ḡ_full‖²−ḡ_A·ḡ_B)/(ḡ_A·ḡ_B)`,
不需逐样本梯度,每次更新给一个精确值。落地前做了三层验证:
合成已知答案(±2%,零模型正确发散)、真 torch `.grad` 端到端(实际配置误差 ≤0.5%)、
功效分析(用实测 `k_eff≈600` 而非名义 d=1.88e7,否则会得到**假的** hi/lo=1.0;
结论是 n=25 即可在 [464,4131] 全区间判决)。

**作业 1038458 在 ai-gpu14 运行中**,当前 n=3(需 25):

| epoch | B_noise | 信号占比 |
|---|---|---|
| 0 | 112 | 91.1% |
| 1 | 295 | 79.6% |
| 2 | 316 | 78.5% |

分析器按纪律**拒绝打判词**(n<25)。趋势提示 epoch 0 是 LoRA 初始化瞬态。

### 5. 又发现仪器本身的一个缺陷,并已修(0064 §⑦/§⑧)

**随机半批切分下,两个半批各含全部 48 个 prompt** ⇒ prompt 专属分量 `p_c` 在两半中完全相同,
内积滤不掉它,**被误算成信号**。⇒ 现有 Gate B 测的是「**同 epoch 内**的噪声尺度」,
**只能判"加每 prompt 图数",判不了"加 prompt 数"** —— 而后者恰恰是 §4.81 指出的那条好路。

修法(已实现并过预检):把 epoch 内洗牌改成"前一半 microbatch 只含 prompt 0–23、
后一半只含 24–47",两半 prompt 不相交。**由 §4.81 的线性性,这不改训练**;
且已逐条核实 OPSD 路径不依赖 `timesteps`、`opa_sig_q` 是全 epoch 常数,
故微批构成确实不影响损失与梯度。新臂 `ARM=bnoisep`,等 gpu17 空出即提交。

## ⑤ 追加(08:10)—— 相干性理论被自己的数据降级,但**指回了 RTC 的原始命题**

## ⑧ 追加(09:55)—— 范数探针出数,查出前两轮的"分歧"整个不成立

范数探针(1038462)产出 `nrm_canon` 后做对账,结果是**作废我自己前两轮的一整条推理线**:

> **§4.86("两估计量差 2~4 倍")与 §4.89("同区间差 1.4 倍")的比较对象不成立。**
> 余弦探针对 **`pos_loss` 单支**求逐样本梯度(L1972),
> 而半批法测的是真正进 optimizer 的 **`r1·pos+(1−r1)·neg`**(L2037)。
> 实测 `neg_loss` 与 `pos_loss` 等量级(0.14522 vs 0.14525)、`r1` 以 0.5 为中心
> ⇒ **两个量本来就不相等**,不是"哪个估计量更准"的问题。

另外还查出对账脚本一个**单位错**:把样本级 `‖G‖²/E‖g‖²` 直接和批级 `‖G‖²/‖ḡ‖²` 比
(二者差一个 `trΣ/B` 项)。换算后 61.1% vs 71.1%,差 1.16×,并非脚本原来判的"不一致"。

**范数数据本身的结论:范数-对齐相关无法断言。**
