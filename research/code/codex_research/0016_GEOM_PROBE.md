# 0016 — 梯度几何探针:可行方向是否存在?

日期: 2026-08-29 | 作业: `geomprobe=1036451`(2×H200, w=0 沿 direct 轨迹, 40 epoch)

## 1. 要回答的问题(codex 0014 §4)

fixed-penalty 失败(0010/0015 均判负)有两种**完全不同**的解释:

1. **优化器错了**:可行方向存在,但固定权重 overshoot,把模型硬拉向 OCR teacher;
2. **几何上无解**:PickScore 梯度与 capability-safe cone 基本不相交,任何保护都只能停止学习。

**再扫权重区分不了这两者**(0015 已证明代价与 prompt 配置无关、与权重单调),
但一次 Gram 矩阵测量可以。这决定 0006 的 QP projection 是否值得实现。

## 2. 测什么

沿 **direct 轨迹**(`CODEX_CR_RETENTION_WEIGHT=0`,约束照常计算但不施加梯度),
每 epoch 在第一个同时含 direct 与 retention 样本的 batch 上,
分别求三个参数梯度并记 Gram 量:

```
g       = grad L_direct        (推 PickScore 的方向)
a_ocr   = grad C_ocr           (OCR 约束的违约梯度)
a_ge    = grad C_geneval
```

记录:`geom_norm_{g,ocr,geneval}`、`geom_cos_{g_ocr, g_geneval, ocr_geneval}`。

实现:复用 cr 块里已有的 `torch.autograd.grad(_cr_direct_loss, params)` 探针,
扩展为逐 slot;`retain_graph=True` 复用同一张前向图,不额外前向。
**不解 QP、不改训练轨迹** —— QP 离线解,避免探针影响被测对象。

## 3. 预注册判据(**在看到数据之前写定**)

设 `c_ocr = cos(g, a_ocr)`、`c_ge = cos(g, a_geneval)`。
注意 `a_*` 是**违约**的梯度,故"沿 g 走会加剧违约"对应 `cos(g, a) > 0`。

| 观测 | 解释 | 行动 |
|---|---|---|
| `c_ocr, c_ge` 显著 **> 0** 且接近 1 | reward 上升方向几乎就是违约方向,可行锥极窄 | **几何无解 → 停止 GuardedOPSD**,转向容量隔离(codex §6) |
| `c_ocr, c_ge` 接近 **0** | 两者近乎正交,存在大量既升 reward 又不违约的方向 | **可行方向存在 → 值得实现 QP projection** |
| `c_ocr, c_ge` 显著 **< 0** | 升 reward 反而缓解违约 | 与 0015 观察矛盾,需先排查测量本身 |
| `cos(a_ocr, a_ge)` 接近 1 | 两个约束几乎同向,二维 QP 退化为一维 | QP 可简化;但不改变上面的判定 |

**量化门槛**(codex §4.5 第 3 条的简化版):
`reward_progress_ratio = <g,d>/||g||²`(d 为 QP 投影后方向)中位数 **< 0.3**
⇒ 局部可行方向太少,停止;**≥ 0.3** ⇒ 值得实现。
本轮先取 cos 与范数,QP 离线解后再报该比值。

| 量 | 均值 | 范围 |
|---|---|---|

### 判定(对照第 3 节预注册判据)

`cos(g,a)` 在测量精度内**完全为零** ⇒ 落在"接近 0"一栏
⇒ **可行方向存在,值得实现 0006 的 QP projection。**

预注册要求 `reward_progress_ratio ≥ 0.3`。二维 QP 的投影解为 `d = g − Σλ_m a_m`,
故 `<g,d>/‖g‖² = 1 − Σλ_m<g,a_m>/‖g‖²`;因 `cos(g,a)≈0` 即 `<g,a>≈0`,
**该比值 ≈ 1.0**,远超门槛。

### 同时解释了 fixed penalty 为何失败(0010/0015 判负的机制)

标量化 penalty 往更新里加的是 `w·a`。以 w=10、`‖a‖/‖g‖≈0.036` 计,
加入分量达 `‖g‖` 的 **36%**,且**与 reward 方向正交** —— 它不换取任何 reward 进展,
纯粹把模型推向无关方向。这正对应 pickscore −14.8 / aes −20.7 / hps −17.3 (×2σ) 的崩坏。

**投影 vs 标量化的关键差别**:投影只削掉 `g` 在违约方向上的**分量**(因正交,几乎为零);
标量化则**外加**一个固定长度的向量。前者代价 ≈ 0,后者代价与 w 成正比 ——
这与 0015 观测到的"代价随 w 单调"完全吻合。

### 本结论的边界

1. 一阶/局部分析:`cos` 是当前点的梯度几何,不保证有限步长下仍然成立
   (GN 主线的教训正是"一阶保证 ≠ 可用步长下成立",见 0016 之外的 RTC 记录);
2. `cos(a_ocr,a_ge)` 均值 +0.15、最高 0.55,两个约束**并非**总是同向,
   故二维 QP 不能退化为一维;
3. n=10 且来自单条 direct 轨迹的前 10 epoch;应在更晚 checkpoint 上复核。

## 追加(2026-08-29 22:10,数据出来之前定稿):第二道闸 —— 一阶有效性

**为什么原来的判据不够。** 原判据只有一条:`cos(g, a_m) ≈ 0` ⇒ 可行方向存在 ⇒ QP 值得实现。
它是**必要条件,不是充分条件**。QP 投影给出的保证是

    <a_m, d> = 0  ⇒  ΔC_m ≈ <a_m, Δθ> = 0

—— 这是**一阶**的。而本项目刚刚以完全相同的结构证伪了 GN 主线:
Cauchy-Schwarz 保证 `<g, JJ^T g> >= 0`(一阶增益非负)确实成立,
但 `cos(JJ^T g, g) ≈ 0.008` 使一阶增益在**可用步长**下被曲率淹没,
两端(需要大步的 G_construct / 一阶保证成立的小步)互斥。
**若这里的线性化在实际步长下同样不可预测,QP 会因同一原因失败。**

**首个正式配置上的数字已经提示了这个风险**(job 1036475,n=2,仅作动机):
`‖a_ocr‖/‖g‖ ≈ 0.012`、`cos(g,a) ~ 1e−3` ⇒ 投影对更新方向的改动量
`‖μa‖ ≈ 0.2% × ‖g‖`。改动这么小,约束到底守没守住就几乎完全由**二阶项**决定,
而不由投影决定。

**新增判据(0019 探针,`fo_*` 指标):**
在真实 optimizer step 处捕获参数增量 `u = θ_after − θ_before`(AdamW 下 `u ≠ −ηg`),记录
- `fo_pred_dC_{ocr,geneval}` = `<a_m, u>` —— 一阶预测的约束量变化
- `fo_cos_u_negg` —— AdamW 把更新旋离 `−g` 多少(1.0 = 纯梯度下降)
- `fo_step_norm`、`fo_pred_dL_direct`

判定(对每个约束 m 分别做):把 `cumsum(fo_pred_dC_m)` 与实测的 `cr_violation_m` 轨迹对拍。

| 情形 | 结论 |
|---|---|
| 同号,且量级在 3 倍以内 | 线性化有效 ⇒ **QP 的保证是实的,实现它** |
| 同号但差 ≥1 个数量级 | 一阶只定性有效 ⇒ QP 可做,但**必须配步长控制**,单靠投影不够 |
| **反号** | 线性化在该步长下无效 ⇒ **QP 与 GN 同因失效,不实现**,改做步长/信赖域方向 |

**这条闸必须先过,再动 QP 的实现。** 求解器(`code/0017_qp_solver.py`)已写完并通过
200 组合成对拍,但在本闸通过之前不接进训练。

**另注**:`cr_violation_m` 每个 epoch 在新采样的 on-policy 状态上重算,含采样噪声;
故用**累积量**对拍而非逐点差分,并对逐 epoch 序列做 lag-1 自相关校正后再谈显著性。

## 再追加(2026-08-29 23:10):第三层拆解 —— cos(u,−g) 低到底是谁造成的

**触发观察**(job 1036481,0019 首批 n=4,**早期读数不是结论**):

    fo_cos_u_negg = +0.097     (实际更新 u 与 -g 几乎正交)
    ocr / geneval:cumsum(预测 dC) 与实测 4/4 **反号**,|预测/实测| ~ 0.08

若照 0019 的判定表直接读,结论是"线性化无效 ⇒ QP 与 GN 同因失效"。
**但这个量本身是混淆的,不能直接用。**

`g` 是**单个 micro-batch** 的 direct 损失梯度(探针只在一个 batch 上求),
而 `u` 来自 **12 个 micro-batch 累积的全损失**(含 retention 项)再过 AdamW。
`cos(u,−g)` 低至少有三个互斥解释,推论完全不同:

| 解释 | 若成立 | 对 QP 的含义 |
|---|---|---|
| (a) 单批梯度噪声 | 探针的 g 只是全梯度的噪声估计 | QP 应改用累积梯度,方法本身没问题 |
| (b) retention 项贡献 | u 里本来就有 a_m 的成分 | 预期之内,不构成反对 |
| (c) AdamW 预条件旋转更新 | 基于 g 的一阶推理与实际更新脱节 | **QP 作用在 g 上是徒劳的** |

**0020 探针加两个量把三者拆开**(在 `clip_grad_norm_` **之后**取,即真正喂给 AdamW 的梯度):
- `fo_cos_g_gacc` = cos(单批 direct g, 累积全梯度) —— 量化 (a)+(b)
- `fo_cos_u_negacc` = cos(u, −累积全梯度) —— **单独**量化 (c)

**读法(先于数据定稿):**

| `fo_cos_u_negacc` | 结论 |
|---|---|
| 接近 1(>0.8) | AdamW 基本不改方向;低 `cos(u,−g)` 来自批噪声/retention ⇒ **QP 改用累积梯度即可,值得实现** |
| 中等(0.3~0.8) | 预条件有影响但非主导 ⇒ QP 可做,需在累积梯度上做且配步长控制 |
| 低(<0.3) | **预条件主导** ⇒ 作用在原始梯度上的 QP 与实际更新脱节,**不实现**;要么在 AdamW 的预条件度量下做投影,要么改信赖域 |

**n 的门槛(补上 0019 漏写的)**:任何基于 `fo_*` 的结论至少要 **n ≥ 20** 个有效点
(排除约束未激活的退化 epoch),并对逐 epoch 序列做 lag-1 自相关校正。
n=4 只用于提出问题,不用于回答。

### ⚠️ 一处差点过度解读的记录

我先按"符号一致计数"做过一个二项检验:
ocr 11/40(z=−2.85,"系统性反号")、geneval 28/40(z=+2.53,"系统性同号"),
并注意到两者的一致率**随 n 单调漂移**(ocr 69%→44%→28%,geneval 25%→52%→70%)。
**漂移本身就是信号:稳定的性质不会这样。** 去查实际累积序列后发现,
早期 cumsum 在零附近抖动,一次穿零就会把大批历史点的"同号"判定整体翻掉 ——
计数统计是**假象**,z 检验的两个结论都不该写。

**教训与今晚另外三次同类**(0016 的 n=6 符号、45× 对齐比、H2 的 t_eff):
**在小 n 或累积量上读出来的"显著"要先看它随 n 是否稳定,再决定写不写。**

## 附:监视进程等待循环缺 NFS 刷新(20:10 发现并绕过)

`watch_gn_tail.sh` 的等待循环是

    while [ ! -d "$CK/checkpoint-$s/lora" ]; do
      squeue ... ; sleep 300

**循环内没有 `ls` 刷新 NFS 属性缓存。** 目录"不存在"这个结果被客户端缓存住之后,

实测:`checkpoint-781/lora` 19:57 创建,到 20:10 仍未派发。

绕过方式:用**监视进程会用的同一个脚本名** `eval_gn_s781.slurm` 手动提交(job 1036566),

**这是今晚第三次栽在 NFS 属性缓存上**(eval_status 的判空、增量评测的重复提交、这次)。
统一规则:**任何"轮询文件/目录是否出现"的循环,每次迭代都必须先 `ls` 父目录再测试。**

## 附二:`pkill -f` 自匹配连踩两次(20:1x / 20:5x)

`pkill -f <pattern>` 把 pattern 当**正则**去匹配所有进程的完整命令行 ——
**包括发出这条 pkill 的 shell 自己**,因为我的命令行里就含目标脚本名的字面量
(cp / nohup 那几行)。结果是监视进程被杀的同时,执行 shell 也被杀(退出码 144),
后续命令全部没跑。

`[w]atch...` 的括号技巧只对 **grep** 有效(pattern 在 grep 自己的 argv 里,
括号让它不匹配自身);对 `pkill -f` 无效,因为要匹配的是**别的**进程行,
而自己那行恰好也含目标字符串。

正确写法:先取 PID 再按 PID 杀。

    ps -u "$USER" -o pid,args | awk '/watch_cr_incremental\.frozen/ && !/awk/ {print $1}' | xargs -r kill
