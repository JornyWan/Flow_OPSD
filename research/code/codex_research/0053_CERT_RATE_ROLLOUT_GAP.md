# 0053 ★ 构造层 vs rollout 层的落差:认证率从 0.95 单调掉到 0.52(2026-08-31 14:20)

**这是用既有数据挖出来的,不是新跑的。** 它给 RTC 主线提供了一个**实测的**机制候选,
而不是推测。

## ① 两个层面的"目标是否更好"

| 层面 | 测什么 | 实测 |
|---|---|---|
| **构造层**(Gate A, open3) | 在 clean 锚点上,目标 `y_plus` 的 reward 是否高于 `y0` | **98.6%** 三轴同升 |
| **rollout 层**(`opa_cert=1`, pickscore) | 从 `y_plus` **继续扩散到终点**,产出的图是否真的更好 | **68.6% 均值,末段仅 52%** |

`opa_cert=1` 的判据是官方代码 `opa_ap = (R_plus >= R_old + margin)`,
其中 `R_plus` 打在 `_dpm2_continue_from(zq, kq, y_plus, ...)` 的**终点图**上。

## ③ 含义

> **构造出的目标"看起来更好"几乎总成立(98.6%),
> 但它是否**在模型的采样流形上可达**,随训练迅速恶化 —— 到 100 updates 只剩 52%,
> 勉强高于抛硬币。**

这直接支持 §4.30 预写的替代机制:**实现缺口的主因不是"拟合阶段不去追目标",
而是"目标本身越来越不在模型 rollout 能到达的地方"。**
与 N2 的结果方向一致(N2 精确移除了拟合梯度的 0-齐次性,却什么都没改变)。

## ④ 必须写清的三条 caveat

1. **单奖励 pickscore,不是 open3。** 故 68.6% 与 Gate A 的 98.6% **不是同一口径**,
   只能作层面对比,不能相减。
2. **来自旧仓库 `DiffusionOPSD-main`**(0041 查出被改过 +201 行)。
   但已逐字核验:`_dpm2_continue_from` 的 md5 与 pristine **完全相同**(`6baa5db2617a`),
   认证块 `opa_ap/opa_am` 两行也逐行相同 ⇒ **该测量本身有效**。
3. **⚠️ 存在混淆:`opa_cert=1` 会改变训练**(未认证的样本被置零,不进损失)。
   所以这条下降曲线是"在认证门控下训练"的轨迹,不是 canonical 训练的轨迹。
   **无法排除"下降部分由门控本身造成"。** 首箱(0.9521)最接近 canonical,越往后混淆越大。

## ⑤ 由 caveat 3 直接得出的下一步

**Cert 探针(只测不门控)**:复制 `opa_cert` 的计算,但**保持 `opa_ap=1.0` 不变**,
只把认证率写进 metrics —— 与 Gate A 对 A1 的关系完全一样。
这样测到的就是 **canonical OPSD 的真实 rollout 可达率**,没有门控混淆。
成本:每 chunk 多两次 rollout 续跑 + 两次打分,与 Gate A 同量级。

**优先级:高于 Gate P。** 理由见 §⑥。

## ⑥ 这对 Gate P / LSR-OPSD 的影响(**不推翻,但要降级预期**)

Gate P 用**clean 目标上的 ΔR**给候选方向打分。而本文说明:
**clean 层面的 ΔR 与"最终图是否更好"之间的关联在训练后期很弱(52%)。**

⇒ **Gate P 是必要不充分的**:即便 P1–P4 全过(说明构造层有局部 Pareto headroom),
LSR 训练臂仍可能因为"选出的目标同样不可达"而打平。
**不改已排队的 Gate P**(它回答的"构造层有没有 headroom"仍是真问题),
但在 0051 里记下这条限制,并在解读结果时不得把 Gate P 通过等同于 LSR 会成功。

**更根本的方向**:把候选方向的评分从 clean 目标改到 **rollout 终点**
(即 Gate P v2 用 `_dpm2_continue_from` 打分)。这才是与最终图对齐的判据。
待 cert 探针确认 canonical 可达率后再定。
