# 0062 预注册:Gate Q2 —— 更好的目标能否通过**参数更新**兑现(2026-09-01 01:50,launch 前写定)

## ① 为什么必须有这一关

Q1b 证明了**能造出更好的目标**(回溯后负增益率 0.0%、均值 +63.3%)。
但 §4.47 的两段分解显示:

    ①构造 → ②rollout:  存活 63.4% → 43.0%
    ②rollout → ③参数更新后实现:  存活 23.9% → **0.2%**

**第二段(②→③)才是损失大头,而 Q1/Q1b 完全没碰它。**

**N2 就是死在这个区别上**:它的假设("拟合不够用力")在构造层看着合理,
实测五轴全平。**"能构造 ≠ 能实现"是本项目最贵的一课,不能再犯。**

⇒ **Gate Q2 不通过,就不排 Q-OPSD 训练臂。**

## ② Q2a(先做,便宜):共享 LoRA 的**梯度相容性**

Codex 0058 §7 明确指出:
> Gate A 的 `+0.715` 是 reward-gain correlation,**绝不是 parameter-gradient cosine**。
> 共享 LoRA 的梯度相容性至今没有在 clean official baseline 上被测过。

**测什么**:对同一 chunk 内的样本 i,分别在两种目标下求**逐样本**的拟合损失参数梯度

    g_i^canon = ∇_θ ‖y_θ(s_i) − y_+^{clean,i}‖²
    g_i^Q     = ∇_θ ‖y_θ(s_i) − y_+^{Q,i}‖²

报告**两两余弦** `cos(g_i, g_j)` 的分布(i≠j),以及各自与批平均梯度的余弦。

**判据(先写后测)**:

| # | 判据 | 含义 |
|---|---|---|
| Q2a-1 | canonical 的 `median cos(g_i,g_j)` | **报告值**(此前从未测过,无阈值) |
| Q2a-2 | Q 目标的 `median cos(g_i,g_j)` **≥** canonical | Q 目标是否让梯度更相容 |
| Q2a-3 | 负余弦对的比例 | 量化"互相抵消"的程度 |

**Q2a-1 无阈值,是纯测量** —— 它本身就是项目缺失的关键数字。
**只有 Q2a-2 成立(Q 让梯度更相容),才有理由预期 Q-OPSD 在参数层也赢。**

## ③ Q2b(Q2a 后做,昂贵):真实 optimizer step 的留出验证

按 0058 §7 的设计:

1. 把同一批 state 对半分 **A/B**;
2. 在 A 上分别用 canonical 目标与 Q 目标形成候选 AdamW 更新;
3. **临时应用**该更新;
4. 在 **B** 上重新生成 exact suffix,量实际的 fixed-suffix 增益;
5. **回滚参数,不产生正式 checkpoint**。

**判据**:Q 目标的更新在留出集 B 上的 suffix 增益 **> canonical 的**,配对 t > 2.5。

## ④ 预写失败模式

- **(a) Q2a-2 不成立**(Q 目标的梯度并不更相容)⇒ 说明第二段损失来自
  **跨样本梯度抵消**,与目标质量无关。**此时改目标构造是徒劳的**,
  应转向 gradient-coherent batching / adapter experts,而不是继续优化目标。
- **(b) Q2a-2 成立但 Q2b 不成立** ⇒ 梯度更相容却仍兑现不了,
  嫌疑指向 **AdamW 预条件旋转**;需测 `cos(g, AdamW(g))`。
- **(c) 两者都成立** ⇒ 才可排 100-update 同种子 A/B 训练臂。
- **(d) 逐样本梯度算不动(OOM/太慢)** ⇒ 先减样本数或用随机投影 sketch,
  **不改判据**。

## ⑤ 成本与顺序

Q2a 需要**逐样本**参数梯度:一个 chunk 内取 8 个样本 ⇒ 8 次 backward(现在 1 次)。
先在小样本上验证可行性,再定规模。
**Q2b 更贵**(要真的走一次 optimizer + 留出集重采样),故排在 Q2a 之后。

**⚠️ 与 Q1/Q1b 的关系**:Q1/Q1b 判的是**目标构造层**,已通过;
Q2 判的是**参数实现层**。两者都过才轮到训练臂。
