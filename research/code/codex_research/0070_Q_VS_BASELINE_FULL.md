## 0. 结论先行

1. **`d_Q`(穿后缀的 action-value 梯度)在训练协议下是真实有效的**:
   正确实现(qcore)在完全匹配的协议上比 baseline **+0.0561**(逐图配对 t=+40.2,胜率 91.1%)。
2. **在官方口径(DrawBench + flow-40)上仍显著更差 −0.0141**(t=−3.53)。
3. **此前"Q 换 sampler 就垮"的读法是错的。** qcore 在六个 sampler 上落在 1.618–1.638 的窄带;
   波动大的是 baseline(1.582–1.664)。Q 是**近似 sampler 无关**的。
4. **由此得到一个正向结果:2.8× 推理步数**(dpm2 家族内,同质量)。
5. **天花板可精确归因**:Q 把它所穿过的 solver 的渐近质量搬到 10 步,
   但继承了那个 solver 的上限;而 DPM2 的渐近低于 flow 的。
6. 主要待办:(a) 单 seed;(b) 建议的下一版是**把 Q 后缀换成 flow**,不是"随机化 solver"。

## 2. 方法与三条臂

官方 OPSD 每个 outer epoch:① 采样 rollout → ② 在 query state(σ≈0.278,第 8/10 步)
沿 reward 梯度做**两步**信赖域上升/下降构造 `y±` → ③ 按 group advantage `r1` 加权拟合。

`d_Q` 的想法(0058):② 用的是 `∇_y R(D(y))` —— 把中间干净图预测**直接解码**的梯度。
但模型最终不输出 `y`,它还要走完后缀。改成

```
∇_y R(D(y))  →  ∇_y R(D(F_old(s, y)))
```

`F_old` = 强制 query 动作为 `y` 后,用**冻结的** old policy 走完剩余步(DPM2 确定性 ⇒ 可微)。

| 臂 | 构造 | 方向 | 回溯 |
|---|---|---|---|
| baseline | 官方两步 | `∇R(D(y))` | 无 |
| **qopsd** | **一步镜像** | `d_Q` | 标量和在线回溯 α∈{1,.5,.25,.125} |
| **qbt** | **一步镜像** | `∇R(D(y))`(方向消融) | 同上 |
| **qcore** | **官方两步** | `d_Q` | **无**(唯一差异就是 oracle) |

## 3. 实现缺陷一:一步严格镜像 ⇒ advantage 从梯度中消失

策略侧本就镜像:`v_pos = v_old + β·δv`,`v_neg = v_old − β·δv` ⇒ `y_pos − y0 = −(y_neg − y0)`。
qopsd/qbt 的目标侧**也**严格镜像 `y± = y0 ± α·budget·unit(d)`。两者叠加:

```
y_pos − y_plus = −(y_neg − y_minus)   逐元素
⇒ 平方项与 |·| 归一化分母都相同,且实测 acc_p ≡ acc_m ≡ 1.0
⇒ pos_loss ≡ neg_loss  ⇒  r1·pos + (1−r1)·neg ≡ pos_loss
```

**group advantage `r1` 对梯度的贡献严格为零。** 实测逐样本 `mean|pos−neg|`:

| arm | mean\|pos−neg\| | 相对 L_pos≈0.2 |
|---|---|---|
| baseline | 1.44e−03 | 7e−3 |
| **qopsd** | **3.50e−07** | 1.75e−06(fp32 舍入量级) |
| **qbt** | **2.48e−07** | 1.4e−06 |
| **qcore(修复后)** | **1.32e−02** | 6.6e−02 |

已核实**只影响这两条臂**:其余 9 条 run(baseline np3/np4、a1、n1、n2、a3、a1v2、b4x、certp)
的相对比都在 4e−3 ~ 3e−1,高出 3–5 个数量级。

baseline 不退化的原因:两步构造的第二步在 `y0±h·g` 处**重算**梯度,reward 曲率打破镜像。
qcore 沿用两步构造,故 `|pos−neg|` 比 baseline 还大 9 倍(后缀放大了两分支的差异)。

**⇒ 因此 qopsd/qbt 训的不是 OPSD,而是"对所有采到的 state 做无条件 reward-ascent 方向回归"。**

## 3b. 实现缺陷二:训练版的回溯不是通过 Gate Q1b 的那个

0058/0061 预注册判据是"标量和增益 > 0 **且**每个 rollout 轴增益 ≥ 0";
训练代码只做 `_ok = (_rj > _r0q)`,而 `_r0q/_rj` 已是三轴标量和。
且 α 只按**正**候选选出,`y−` 直接镜像得到,**从未验证** `Q(y−) < Q(y0)`。
⇒ "Gate Q1b 通过"不能作为训练实现的证据。qcore 已彻底去掉回溯。

## 7. ★ 天花板归因:Q 继承了它所穿过的 solver 的上限

```
baseline 的 dpm2 渐近(40 步) = 1.6482    ← Q 训练时穿的就是 dpm2
baseline 的 flow 渐近         = 1.6637

qcore 天花板 = 1.6382(在 dpm2-10)  比 dpm2 渐近低 0.0101,比 flow 渐近低 0.0255
qopsd 天花板 = 1.6413(在 dpm2-10)  比 dpm2 渐近低 0.0070

baseline 的 dpm2 10→40 增益 = +0.0662   ← 它在 10 步付的「离散化罚金」
qcore    的 dpm2 10→40 增益 = −0.0086   ← 罚金已被消掉,没有可再赚的
```

`qcore@dpm2-10` 与 `baseline@flow-40` 的差 **−0.0236** 可精确分解:

| 来源 | 值 | 占比 |
|---|---|---|
| flow 渐近 − dpm2 渐近(**solver 家族**) | +0.0136 | 57% |
| dpm2 渐近 − qcore 天花板(**Q 自身残余不足**) | +0.0101 | 43% |
| 合计 | 0.0237 | 实测 0.0236 ✓ |

**机制解读(待证伪):** `d_Q` 优化的是"**10 步 DPM2 的终点**"的 reward。
它教会策略把 DPM2 的渐近质量在 10 步就实现(罚金 +0.0662 → −0.0086),
但它**无法超过 DPM2 自己收敛到的水平**,因为那正是它所微分穿过的算子。

### 由此得到的正向结果:2.8× 推理步数

| | dpm2 步数 | 目标合计 |
|---|---|---|
| **qcore** | **10** | **1.6382** |
| baseline | ≈**28**(20→40 按 log2 内插) | 1.6382 |

逐图配对验证穿越点:

| 对比 | Δ | t | 胜率 |
|---|---|---|---|
| qcore@10步 − baseline@dpm2-20 | **+0.0098** | **+7.7** | 60.0% |
| qcore@10步 − baseline@dpm2-40 | −0.0101 | −8.5 | 38.1% |
| qcore@10步 − baseline@flow-40 | −0.0236 | −20.1 | 23.5% |

10 步与 40 步 baseline 的质量差是 0.0797,**qcore 在 10 步补上了其中 70%**。

## 8. 想请 review 的三点

### (a) 天花板归因是否成立?

上面的分解在数值上完美(0.0237 vs 实测 0.0236),但**只有一个数据点支持机制解读**。
如果成立,**下一版应把 Q 后缀从 DPM2 换成 flow**(评测用的那个 solver),
预期能拿回 57% 的差(+0.0136)。这与我们原先计划的"随机化 solver 与步数"是**不同的**方案 ——
后者的动机(Q 波动大)已被 §6 的数据否掉。

**这个改动的实现风险**:`_dpm2_continue_from_grad` 用的是多步 DPM 求解器,
`st.model_outputs[-1] = prev_x0` 这个状态种子与网格耦合;换成 flow(一阶 Euler)反而**更简单**
(无历史状态),风险低于重离散化方案。

### (b) 2.8× 这个说法能不能立得住?

- 只在 **dpm2 家族内**成立;对 flow-40 仍落后 −0.0236。
- 步数 ≠ NFE(dpm2 是二阶)。严格效率主张应按 NFE 重算 —— **尚未做**。
- old(behavior)adapter、unseen Pick-a-Pic prompt。default adapter 下的步数曲线**未测**。

### (c) 还缺的控制

1. **单 seed**(seed 20260830)。所有 Q 臂与 baseline 共享同一 seed。
2. `git_commit="unknown"`,`RPI_*` 是 env 型干预不进 `run_config.json`
   (已用 `arm_provenance.json` 补,但 qopsd 运行时的旧格式缺 `RPI_QOPSD_DIR`)。
3. qcore 只跑到 ck100;baseline 已知在 ck100 **远未收敛**
   (ck200 = 1.6805,比 ck100 高 +0.0457,t=+11.2)。**qcore 的 ck200 未测。**
   ⇒ 现有全部 Q 判定都是"在一个离收敛还差 4.5 个 MDE 的早停点上比高低"。
