## ② 要检验的前提(可能否掉我们自己)

## ④ 预注册判据(先写死,不许事后调)

主统计量:**向量可行率** `VFR = P(Δ_plus[k] > 0 对全部三个 k 同时成立)`。

| VFR | 判定 | 行动 |
|---|---|---|
| **≥ 0.90** | 标量求和本来就产生 Pareto 改善目标 | **A1 无立足点 → 杀掉 A1**,只保留 A2(post-fit gate) |
| **≤ 0.60** | 存在大量以一轴换另一轴的目标 | A1 成立,进入实现 |
| 0.60 ~ 0.90 | 不明确 | 报告逐轴 `mean Δ_plus[k]` 与各轴单独为负的比例,**再决定,不默认放行** |

辅助统计量(一并预注册,不作主判据):
1. 逐轴 `P(Δ_plus[k] < 0)` —— 哪一轴最常被牺牲;
2. `corr(Δ_plus[pick], Δ_plus[hps])` 等三对相关 —— 是否存在结构性对立;
3. 换一组 suffix seed 后 VFR 的重测差 —— 稳定性。

**Kill 条件(明写):**
- 若 VFR ≥ 0.90,**不得**通过"放宽容差把 Δ>0 改成 Δ>−τ"来让 A1 复活;
- 若三轴 `mean Δ_plus[k]` 全为正且各轴为负的比例均 <10%,同样判 A1 无价值;
- 本探针**不看任何 held-out 评测结果**,只看构造阶段的 reward 增量,避免用测试集校准。

## ⑩ A1 已实现(2026-08-30 16:05,先于 Gate A 判决;写代码不等于放行)

**预注册纪律澄清:** Gate A 决定的是**是否运行** A1,不是是否写它。
判据由数据算出,与代码是否存在无关。提前写好只是为了 Gate A 一出结论就能立刻跑。

### 落点极小:复用官方自己的接受权重

官方损失是 `pos_loss = accp * (y_pos - y_plus)**2 / wf_p`,其中 `accp` 来自 `opa_ap`。
canonical 路径把它**硬编码为 1.0**;`opa_cert=1` 路径则用**标量和**的实测来判。
**A1 = 把那个 1.0 换成逐 reward 判定**,不新增任何损失项:

```python
elif _A1_ON and _ga_r0 is not None:
    with torch.no_grad():
        _ = _reward_of_latents_grad(pipeline, ri_scorer, opa_kind, y_plus.detach().float(), prm)
    _a1_rp = {k: v.clone() for k, v in _GATEA_LAST.items()}
    _feas = None
    for _k in sorted(_ga_r0):
        _ok = ((_a1_rp[_k] - _ga_r0[_k]) >= -_A1_TOL).float()
        _feas = _ok if _feas is None else _feas * _ok
    opa_ap[s:e] = _feas.to(opa_ap.device).to(opa_ap.dtype)
    opa_am[s:e] = 1.0
```

`_A1_TOL` 默认 **0.0**(严格),与 §④ 的 VFR 定义一致 —— 判据和干预用同一个门槛,不另设。

### 指标自动到位,不必新增

既有的 wandb 记录点已经在记 `"opa_acc_plus": float(opa_ap.mean())`。
**A1 下 `opa_ap` 就是可行性掩码 ⇒ 这个指标自动变成可行率。**
canonical 下它恒为 1.0(硬编码常量,见 0034 §⑩);**A1 下它才第一次含信息。**

### 一个 `compile()` 抓不到的 bug(已修)

初版在 A1 块里写了 `info_accumulated["a1_feasible_rate"].append(...)`。
但 `info_accumulated` 到 **~L1526** 才定义,而 A1 块在 **~L1379** ——
运行时 `NameError`,**`compile()` 通过、只有跑起来才炸**。
已删除,改用上面那个既有指标。
⇒ 教训与"不能只看 exit=0"同源:**compile 通过也不等于能跑**。

`RPI_A1=0` 时:`_ga_r0` 因 `(_GATEA_ON or _A1_ON)` 为假而取 None ⇒ 不做额外前向;

## ⑪ Open3 baseline 的实测暴露了 A1 定义的一个缺口(2026-08-30 16:10)

open3 臂 ck20/ck50 的 held-out 结果(OPSD 原生协议):

| | Pick | CLIP | HPSv2.1 | Aes | ImgR |
|---|---:|---:|---:|---:|---:|
| base | 20.5868 | 0.2408 | 0.2070 | 5.1248 | −0.5481 |
| open3-ck20 | 23.3271 | 0.2712 | 0.3289 | **6.2693** | 1.0856 |
| open3-ck50 | 24.1154 | 0.3053 | 0.3534 | **5.9740** | 1.3292 |

**两点都是 5/5 列高于 base。但 ck20→ck50 之间:**
- **被训练的三轴齐升**:Pick +0.79、CLIP +0.035、HPS +0.025(ImgR +0.24 也升);
- **未被训练的 Aes 掉 −0.295 = 13×2σ**(σ_aes=0.01118,0034 §⑦ 实测),极显著。

### 这对 A1 意味着什么

**A1 现在的定义只在 objective 内的三轴上做 veto**(pick/clip/hps),
而实测显示**权衡发生在 objective 之外的轴上**(Aes)。
⇒ 若 Gate A 判 VFR 高(三个被训练的 reward 通常齐升),**A1 现形态会近似空操作** ——
这与 §⑦/§⑧ 记的不利先验一致,现在有了直接证据。

### 处理方式:加测量,不改判据

- **§④ 的 VFR 判据不动。** 它问的是"标量求和在 objective 内是否做权衡",
  这个问题仍然要答,且答案会直接决定 A1 现形态的生死。
- **新增一个辅助量 `VFR_all`(含 Aes/ImgR)不在本次探针内做。**
  理由:`ri_scorer` 对 open3 只载三个 scorer,加 Aes/ImgR 要额外载模型、改代码,
  而 Gate A 约 17:40 就要跑,临时改动的 bug 风险高于收益。
- **Aes 现象可以从已有的 checkpoint 评测直接刻画** —— 那些评测本来就算了 5 列,
  不必动探针。open3 的 ck100(约 18:28 落盘)会再给一个点。

### 由此产生的一个**新候选**,记下但不放行

**A1′ = 把未训练轴纳入 veto**(至少 Aes)。
它比 A1 更贴合实测:被训练的轴自己会升,真正需要保护的是没进 objective 的轴。
但**在 Gate A 出结论前不实现、不排队** —— 否则就是看着数据改方法,
预注册就失去意义。**若 Gate A 判 A1 死,A1′ 需要自己的 gate,不能直接继承 A1 的名额。**

### 修正后的框架(判据数值一字不改)

| VFR | **初步判定** | 之后要做的事 |
|---|---|---|
| ≥ 0.90 | A1 现形态**在 objective 内无立足点** | **进入诊断**,不是终结 |
| ≤ 0.60 | A1 现形态**有立足点** | 实现并跑 A/B |
| 0.60~0.90 | 不明确 | 看逐轴统计与分 epoch 趋势 |

### 预注册要防的到底是什么

**防的是"看到数据再挪阈值",不是防诊断。** 两者的界线:

- ❌ **不允许**:VFR=0.93 → 把判据从 `Δ>0` 改成 `Δ>−τ` 让它变成 0.55 → 宣布 A1 成立。
  这是回头改这一次测试的判据,结论就没有意义了。
- ✅ **允许且应该做**:VFR=0.93 → 判定 A1 现形态无立足点 → **诊断为什么** →
  发现"权衡发生在 objective 之外的轴(Aes,见 §⑪)" → 提出 **A1′**(把未训练轴纳入 veto) →
  **给 A1′ 写它自己的预注册与判据** → 跑它。

差别在于:前者是**同一次测试**换判据,后者是**新的测试**带新判据。

### 已知的候选诊断方向(在看结果之前先列出,避免事后编故事)

若 VFR 高,可能的原因至少有:
1. **veto 的轴选错了** —— §⑪ 已有直接证据:被训练的三轴齐升,而未训练的 Aes 掉 13×2σ。
   ⇒ 对应调整 A1′。
2. **容差取 0 太严/太松** —— 逐样本噪声远大于均值的重测 σ;
   `Δ>0` 在样本级可能几乎总成立(噪声主导)。⇒ 需看逐轴 `P(Δ<0)` 的绝对水平判断。
3. **测错了时点** —— 只测了从 base 起步的 epoch 0~5(§⑨ 边界 2);
   §⑧ 显示单 reward 的权衡发生在**峰值之后**。⇒ 需补中期探针。
4. **rank 0 采样偏差** —— §⑨ 边界 1。⇒ 需扩到全 rank 再确认。

**这四条是先写下来的,不是看到结果后挑一个来解释。**
报判定时会逐条对照实测数据说明哪条被支持、哪条被排除。

## ⑬ A/B 结果的成因清单(**先于数据**写下,防止事后挑解释)

用户 2026-08-30:"得到结果后可以思考可能是什么原因,因为不一定是 idea 不 work,
可能是什么需要调整"。为避免事后编故事,把各种可能结果对应的候选成因先列全。
报结论时**逐条对照实测**说明哪条被支持、哪条被排除,而不是只讲一个顺手的。

### 情形 1:A1 与 baseline 五轴全打平

| 候选成因 | 怎么验 |
|---|---|
| a. veto 几乎从不触发(可行率≈1) | 看 `opa_acc_plus`(A1 下即可行率)的均值与轨迹。**这是最可能的**,与 §⑦/§⑧/§⑪ 的先验一致 |
| b. 触发了但被 veto 掉的样本本来贡献就小 | 比两臂的 `total_loss` / `opa_pos_loss` 轨迹;若几乎重合则支持 |
| c. 100 updates 太短,差异还没积累出来 | 看两臂逐 epoch reward 轨迹是否已分叉;未分叉则需更长预算才能判 |
| d. 容差 0 在**样本级**过松(噪声主导 Δ 的符号) | 看 Gate A 的逐轴 `P(Δ<0)`;若≈0.5 说明 Δ 基本是噪声,veto 等于随机丢样本 |

### 情形 2:A1 显著更差

| 候选成因 | 怎么验 |
|---|---|
| e. veto 丢掉了太多样本 ⇒ 有效批量变小 | 看可行率;若 <0.5 则等于批量腰斩,**这是设计缺陷不是 idea 错** ——
   对应调整:被 veto 的样本按组重填(官方 `opa_topk` 就是这么守恒的) |
| f. veto 引入了系统性选择偏差(只留"容易的"样本) | 比两臂被保留样本的 reward 分布 |
| g. 三轴同升的样本恰恰是信息量最低的 | 看 baseline 中三轴同升样本的 `opa_delta_res` 是否偏小 |

### 情形 3:A1 显著更好

| 需要排除的替代解释 | 怎么验 |
|---|---|
| h. 只是"训得少"(veto ⇒ 有效更新变小 ⇒ 过优化更轻) | 比 Aes 轨迹:若 A1 只是把 baseline 的曲线**沿时间拉长**,那不是新机制,是学习率效应。
   对应控制:再跑一个 baseline-lr 降低到与 A1 有效步长匹配的臂 |
| i. 种子巧合 | 同 seed 配对已排除大部分;但仍需第二个种子确认 |
| j. 评测噪声 | 判据已含 |差|>2σ 且 |t|>2.5 双条件 |

### 情形 4:各轴互有胜负

需要区分"真 Pareto 改善"与"沿 Pareto 前沿滑动"。
判法:看**是否存在某一轴显著更好且无任何轴显著更差**。若不存在,则是滑动不是改善;
此时 A1 的价值需要另找依据(如更稳定、更少过优化),而不能声称 Pareto 改善。

### 一条通用的自我约束

**若实测支持的是"设计缺陷"类成因(e/h 这种),那意味着 idea 需要调整而非否定 ——
但调整后的版本必须重新跑 A/B,不能拿调整前的数据说"其实它是好的"。**
