## 0b. 那么真正的效应是什么

把两个口径并排看,OPSD 训练改变的不是 OCR 本身,而是**模型对 CFG 的响应幅度**:

| | gs=1.0 | gs=4.5 | CFG 增益 |
|---|---:|---:|---:|
| base SD3.5-M | 0.1306 | 0.5494 | **+0.4188** |
| OPSD-pickscore ck20 | 0.2173 | 0.4284 | **+0.2111** |

**OPSD 臂在 gs=1.0 起点更高、在 gs=4.5 终点更低,CFG 带来的增益几乎腰斩。**
即 CFG-free 训练消耗掉了模型的 "CFG headroom"。

这是一个**真实但完全不同的**主张,且**尚未定稿**:
- 只有 ck20 的 gs=1.0 对照跑完,ck100 的 ocr 仍在跑 —— 单点不足以定论;
- 需要确认它是 OPSD 特有,还是"任何 CFG-free 训练都会如此"(缺对照臂);
- 若成立,它影响的是**评测口径的选择**,不是"能力被破坏"。

## 0b2. 对照全部跑完(14:27):真实效应远比原主张强,且方向相反

ck20 与 ck100 的 gs=1.0 对照均已完成。**在训练匹配口径下,OPSD 训练三轴全升,且随训练单调增强:**

| 轴 | ck | gs=4.5 Δ(t) | **gs=1.0 Δ(t)** | |
|---|---:|---:|---:|---|
| OCR | 20 | −0.1210 (−4.09) | **+0.0867 (+4.31)** | 符号翻转 |
| OCR | 100 | −0.0721 (−2.41) | **+0.2265 (+10.97)** | 符号翻转 |
| GenEval loose | 20 | +0.0781 (+2.57) | +0.0703 (+2.20) | 同号 |
| GenEval loose | 100 | +0.0469 (+1.53) | **+0.1680 (+5.07)** | 同号增强 |
| GenEval strict | 20 | −0.0156 (−0.45) | +0.0039 (+0.14) | 符号翻转 |
| GenEval strict | 100 | **−0.0977 (−3.01)** | +0.0430 (+1.39) | 符号翻转 |

**CFG headroom 随训练单调塌缩**(同一 checkpoint 在两个 gs 下的 OCR 差):

| | gs=1.0 | gs=4.5 | CFG 增益 |
|---|---:|---:|---:|
| base | 0.1249 | 0.5685 | **+0.4436** |
| OPSD ck20 | 0.2173 | 0.4284 | +0.2111 |
| OPSD ck100 | 0.3571 | 0.4774 | **+0.1203** |

### 正确的结论

> **DiffusionOPSD 的 CFG-free 训练把能力从"靠 CFG 外挂"迁移为"模型内建"。**
> base 在 gs=1.0 下 OCR 仅 0.1249,靠 CFG 拉到 0.5685;训练 100 步后模型自身达到 0.3571,
> 而 CFG 只能再贡献 0.1203。三个点(base / ck20 / ck100)单调,ck100 的 OCR 提升 t=+10.97。

**方法学推论(对本项目直接有用):**
**拿高 CFG 去评测 CFG-free 训练出来的模型,会系统性低估它。**
论文自己用 gs=1.0 评测是正确的;我们此前用 gs=4.5 的 OPD 协议去评 OPSD 臂,是口径错配。

### 仍需注意的边界

- 三个点来自同一次训练,强自相关;有效证据是每点各自在 256/512 个独立 prompt 上的配对检验;
- 尚缺"是否任何 CFG-free 训练都如此"的对照臂 —— 现在只能说这是 OPSD 训练的**伴随现象**,
  不能说是 OPSD 特有;
- **一个尚未检查的连带问题**:我们自己的 `crd`/`crg` 臂训练与评测同为 gs=4.5(已核对),
  内部一致,不受本条影响。但若 reward 训练普遍降低 CFG 依赖,
  则**在 gs=4.5 下评我们的臂是否也低估了它们**,值得单独查一次。**尚未查,不作结论。**

# (以下为原文,主张已作废)


**这是本项目第一次把"reward 直推会毁掉任务能力"这件事,测在 *论文自己的臂* 上**
(OPSD-pickscore,从 base SD3.5-M 训,100 updates),而不是我们自己构造的续训对照。

## ① 方法

- 评测口径:**DiffusionOPD 协议**(GenEval / OCR,gs=4.5,n=256),
  与 `base_gs4.5`、`Student` 同协议。注意这与 0033 §⑫ 的 OPSD 原生协议是两套口径,不可混用。
- **必须配对**:base 评了 512 个 prompt、各 arm 只有 256 个。
  直接比总均值会引入子集偏差 —— base 全 512 条 OCR=0.5688,
  但在 arm 用的那 256 条上 base 只有 **0.5494**(差 0.019)。下表一律用**共同 prompt 配对**。

## ② 结果(Δ = arm − base,配对,n=256 个共同 prompt)

| checkpoint | OCR Δ | t | GenEval strict Δ | t | GenEval loose accuracy Δ | t |
|---|---:|---:|---:|---:|---:|---:|
| ck20  | **−0.1210** | **−4.09** | −0.0156 | −0.45 | +0.0781 | +2.57 |
| ck40  | **−0.1320** | **−4.23** | −0.0742 | −2.24 | +0.0820 | +2.93 |
| ck60  | **−0.1099** | **−3.70** | −0.0547 | −1.53 | +0.0625 | +1.95 |
| ck80  | **−0.0758** | **−2.63** | −0.0742 | −2.15 | +0.0742 | +2.24 |
| ck100 | −0.0721 | −2.41 | **−0.0977** | **−3.01** | +0.0469 | +1.53 |

判据:|t| > 2.5 **且** |Δ| > 2σ(σ_ocr=0.0200 ⇒ 2σ=0.040;σ_accuracy=0.0297 ⇒ 2σ=0.059)。

- **OCR:5 点中 4 点同时满足两条判据**(ck100 的 |t|=2.41 略低于阈值,但 |Δ|=0.072 仍 >2σ);
- **GenEval strict:ck100 满足两条**(t=−3.01,|Δ|=0.098 > 0.059);
- **GenEval loose accuracy:方向为正,ck20(t=2.57, Δ=+0.078)与 ck40(t=2.93, Δ=+0.082)两点同时满足两条判据**,其余三点不满足。

## ③ 读法:这是 reward hacking 的典型签名

三个轴方向一致且互相印证:
**更常通过"宽松的物体存在"判定(loose accuracy ↑),却更常失败于"严格构图"与"文字渲染"
(strict ↓、OCR ↓)。** 即图更"像那么回事"、更讨好偏好模型,但细节是错的。

这与 0028b same-image 诊断独立吻合(无保护臂:任务指标 −5.02,而 Pick/HPS +31.03/+18.08 ——
更好看的图、错的文字与物体)。两者一个是**我们的续训臂**、一个是**论文自己的 from-base 臂**,
在不同起点、不同协议下指向同一机制。

## ④ 一个排除"任何适配都会掉"的对照

| | OCR(gs=4.5) |
|---|---:|
| base | 0.5688 |
| OPSD-pickscore ck100 | 0.4774 |
| **DiffusionOPD Student(教师蒸馏)** | **0.9273** |

教师蒸馏把 OCR 从 0.5688 抬到 0.9273。**所以掉 OCR 不是"加 LoRA 就会掉",
是 reward-only 训练特有的代价。**

## ⑤ 必须写清的三条限制

1. **五个 checkpoint 来自同一次训练,彼此强自相关。**
   它们**不是 5 次独立实验**,不能对它们做符号检验或当作 5 个独立证据。
   有效证据是**每个点各自在 256 个独立 prompt 上的配对 t 检验**;
   跨 checkpoint 的一致性只是"不像是单点偶然"的佐证。
2. **gs 混淆尚未排除。** OPSD 是 **CFG-free rollout** 训练的,而这里在 **gs=4.5** 下评测,
   对它属于 OOD。已派对照(job 1037105:`opsdck20g1` / `opsdck100g1`,gs=1.0,同 n)。
   参考点:base 在 gs=1.0 下 OCR 只有 **0.1249**(gs=4.5 时 0.5688)⇒ **gs 对 OCR 影响极大**,
   这条对照不做完,§② 的结论只能限定在 "gs=4.5 口径下"。
3. n=256,单次训练运行。要升级成论文级结论需要独立 seed(用户已明确暂缓)。

## ⑥ 为什么这条重要

项目此前的处境(0022):RTC 主线证伪、GuardedOPSD 只能主张"把自己造成的损害从 −10.9% 压到 −2.0%"、
唯一超基线的 poe125 是窄胜。**"减少自身损害"之所以听起来弱,是因为损害是我们自己引入的。**

本文把同一损害测在**论文自己的方法**上:OPSD 从 base 训 100 步,OCR 掉 0.07~0.13(13~24% 相对)。
⇒ 这不再是"我们的续训方式有问题",而是**该类方法固有的代价**,
从而使"如何在直推 reward 时保住任务能力"成为一个**有出处的问题**,而不是自设的靶子。
