## ① 为什么需要这道门

§4.78 由 `ρ=0.00151`(canonical 逐样本梯度平均两两余弦)推出
"批梯度 37% 的能量是采样噪声,4× batch 可降到 12%",并把"增大 batch"列为
**idea #8 —— 目前唯一一条不属于 target-side 的改进方向**
(target-side 已被 0063 的 Q2a-2 判定为徒劳:更好的目标使梯度相干性**减半**)。

**但 §4.78 只用了 ρ 的点估计。** 2026-09-01 用全部 Q2a+Q2c 数据、
**按记录聚类**(同一记录内 15 个余弦共享样本,不独立)重估:

| | ρ | SE | t | 95% CI | `B_noise=(1−ρ)/ρ` |
|---|---|---|---|---|---|
| canonical(合并 n=262 记录) | +0.00120 | 0.00049 | **+2.46** | [+0.00024, +0.00215] | **835**,CI **[464, 4131]** |

两点必须记录:
1. **t=+2.46 未过项目既定的 \|t\|>2.5 判据** —— 连 "ρ>0" 本身都只是勉强;
2. **B_noise 的 CI [464, 4131] 把当前 `B_eff=1152` 夹在中间**,两端相差 8.9 倍。

⇒ **现有数据无法判定 4× batch 是有效还是浪费。** 用两两余弦估 ρ 效率太低:
要把 CI 收窄到能判决约需 8× 数据(≈9 小时探针)。**换仪器,不是加数据。**

## ② 仪器:半批(McCandlish)梯度噪声尺度

设逐样本梯度 `g_i = G + ξ_i`,`E[ξ]=0`,`tr Σ = E‖ξ‖²`。把一次更新的
`B` 个样本切成两个不相交半批 A、B(各 B/2):

- `E[ḡ_A · ḡ_B] = ‖G‖²`  ← 噪声在两半间独立,内积无偏地滤掉噪声
- `E‖ḡ_full‖² = ‖G‖² + trΣ/B`

⇒ **`B_noise ≡ trΣ/‖G‖² = B·(‖ḡ_full‖² − ḡ_A·ḡ_B) / (ḡ_A·ḡ_B)`**

`B_noise` 是**临界批量**:`B ≪ B_noise` 时增大 batch 近似线性提速;
`B ≫ B_noise` 时收益递减,增大 batch 基本是浪费算力。

**为什么这个仪器好得多**:
- **不需要逐样本梯度** —— 只要在累积到一半时快照一次 `.grad`(18.8M 参数 ×fp32 = 75MB);
- 每次更新给出**一个**基于全部 1152 个样本的数,而不是 15 个两两余弦的噪声平均;
- 比值量,**fp16 GradScaler 的缩放因子自动约掉**(scale 在一个 step 内恒定)。

**前提已验证**:训练批在切 microbatch 前由 `perm = torch.randperm(total_batch_size_filtered)`
(`train_opsd_ri_sd3.py:1777`)全局洗牌,故"前半 microbatch"与"后半"可交换,
半批切分不引入顺序偏倚。(此事实是 2026-09-01 为 Q2c 另一问题查证的,此处复用。)

**实现要点**:累积计数器 `current_accumulated_steps`、每 microbatch 反传
`loss/effective_grad_accum_steps`(`:2245`)。故累积到第 `m/2` 步时
`.grad = ḡ_A/2`,累积满时 `.grad = ḡ_full`,于是 `ḡ_A = 2·g_half`、`ḡ_B = 2·(g_full − g_half)`。
DDP 每次反传做跨秩平均,两次快照同样处理,半批仍是不相交样本集,估计量不变。
本配置 `accum=48`(3 卡:bs=8,48 microbatch),半分点 = 24,整除。

## ③ 判据(**先写后测**)

聚合:每次参数更新产出一个 `B_noise` 记录;跨更新用 **中位数** 与
**bootstrap 95% CI**(比值量重尾,不用均值±1.96SE)。

- **B-a 方向判定**(主判据,三选一,互斥且穷尽):
  - CI 上界 `< 1152` ⇒ **已在临界批量之上** ⇒ **idea #8 判负**,不跑 4× 臂;
  - CI 下界 `> 2304`(=2×B_eff) ⇒ **明确低于临界** ⇒ 4× batch 有据,进算力配平 A/B;
  - 其余 ⇒ **判定为"未决"**,如实记录,**不得凭点估计二选一**。
- **B-b 精度门槛**(不满足则**拒绝打判词**,不是"凑合下结论"):
  n_updates ≥ 50 **且** CI 宽度比 `hi/lo < 3`。
- **B-c 漂移**:分别报前半/后半训练的中位 `B_noise`。若后半 ≥ 2× 前半,
  则"固定 batch"这个提法本身有问题,须在结论中写明,B-a 只对早期有效。
- **B-d 健全性(零模型)**:要求 `ḡ_A·ḡ_B > 0` 的更新占比 ≥ 90%。

## ④ 预写失败模式(出现即照此解读,不得事后改口)

- **(a) B-d 不过**(内积常 ≤0):`‖G‖²` 在 B=1152 下根本不可分辨 ⇒
  批梯度近乎纯噪声。这本身是**重大发现**,并意味着 batch 是唯一杠杆(B-a 自动落入"低于临界")。
- **(b) B-a 判"高于临界"**:idea #8 死。届时 target-side(Q2a 已杀)与 batch-side 双双关闭,
  **必须换一条真正新的方向**,不得回头调 rho/λ 复活旧臂。
- **(c) B-a 判"低于临界"**:才允许排 4× batch 臂,且**必须算力配平**
  (B×4/25 updates vs B×1/100 updates,总样本相同)。
  ⚠️ "B×4 跑满 100 updates vs B×1 跑 100 updates" 是 4× 算力对 1×,
  几乎必赢且**毫无信息量**,预先禁止用该口径下结论。
- **(d) B-b 不过**:只报区间,明确写"未决",不进入任何后续决策。

## ⑤ 成本

探针只加两个参数量级缓冲与每次更新几个点积,**不改训练数学**
(不进 `loss`、不改 `.grad`、快照后不写回)。可挂在任何一条已排队的臂上零成本采集。

## ⑥ 功效分析(**在任何真实数据产出之前**算的,2026-09-01)

比值估计量在小 n 上有有限样本偏差,先确认这道门**能不能判决**,再决定跑不跑。
关键参数是**噪声的有效维** `d_eff`:`‖ξ‖²` 的相对涨落 ≈ `√(2/d_eff)`。
若按名义参数量 `d=18,776,064` 算,CI 宽度比会是 1.0 —— **那是假的精确**。
噪声实际只活在 §4.79 实测的 `k_eff≈600–1300` 维子空间内,须用 `d_eff=k_eff`。

`d_eff=600`(悲观端)、B=1152、bootstrap 95% CI:

| 真值 `B_noise` | n=25 | n=100 | 判决 |
|---|---|---|---|
| 400 | [364, 420] | [379, 419] | ✅ 判"高于临界" |
| 835 | [829, 969] | [762, 844] | ✅ 判"高于临界" |
| 1152 | [1146, 1357] | [1067, 1180] | 未决(**本就在临界上**,是正确行为) |
| 2500 | [2304, 2803] | [2331, 2686] | ✅ 判"低于临界" |
| 4131 | [2999, 4026] | [3781, 4495] | ✅ 判"低于临界" |

⇒ **在余弦法留下的整个未决区间 [464, 4131] 上,这道门都能判决**;
`hi/lo ≤ 1.3`,B-b 门槛(<3)有大幅余量。
**n=25 次更新(≈3 小时,3 卡)已足够覆盖大部分区间**,不必等满 100。
故把 B-b 的 n 门槛定为 **n_updates ≥ 25**(原写 ≥50,此处放宽并说明理由:
功效分析显示 n=25 的 hi/lo≈1.2,已远优于门槛;此改动在数据产出前完成)。

**估计量本身的已知答案自检**(合成数据,真值已知):
- 向量化模拟:B ∈ {48,192,1152,4608} × 真值 ∈ {100,464,835,1152,4131},
  全部在真值 **±2%** 内还原,且**不随 B 系统漂移**;
- 零模型 `G=0`(纯噪声):`ḡ_A·ḡ_B` 均值 = −4.5e−5 ≈ 0,`B_noise_hat` 爆到 −6e6 ⇒ 正确发散;
- 逐样本全模拟(不走"半批均值是高斯"这个捷径)在 n=400 时于真值 100/661 处
  还原为 101/648,验证了半批均值假设本身。

## ⑦ ⚠️ 仪器缺陷(**首条数据到达后立即记录,先于任何判读**)

作业 1038458 的第一条记录:`ḡ_A·ḡ_B=4100.5`、`‖ḡ_full‖²=4499.8` ⇒ `B_noise=112`,
信号占比 91.1% —— 与余弦法的 595–835 差约 5 倍。查因,发现**估计量本身有系统性偏差**:

**随机半批切分下,两个半批各含全部 48 个 prompt 的样本**,
于是 §4.81 测出的 prompt 专属分量 `p_c` 在两半中**完全相同**,内积滤不掉它:

```
E[ḡ_A·ḡ_B] = ‖G‖² + E‖p‖²/48 = 0.00166 + 0.01134/48 = 0.001896   ← 把 prompt 分量当成信号
E‖ḡ_full‖² = 上式 + E‖ξ‖²/1152                        = 0.002753
⇒ 本仪器测的是「**同 epoch 内**的噪声尺度」,预测 ≈ 521,而不是跨 prompt 的 ≈ 595
```

**这不是 bug,是测错了对象。** 两个问题必须分开,且正好对应 §4.81 的两条加 batch 路径:

| 想加什么 | 相关噪声 | 本仪器能否判 |
|---|---|---|
| **每 prompt 图数**(24→96) | 只有 epoch 内样本噪声 | ✅ 直接可判 |
| **prompt 数**(48→192) | 含 prompt 抽样噪声 | ❌ 需把半批**按 prompt 切** |

**修正判据(适用范围收窄,阈值不变):**
§③ 的 B-a/B-b/B-c/B-d 全部保留,但结论**只对"增加每 prompt 图数"有效**;
`4× batch` 若通过增加 prompt 数实现,本门**不构成判决**,须用下述 §⑧ 的按 prompt 切分版本。

**残余差异**:实测 112 vs 预测 521,仍差 4.6×。最可能是
**`upd=0` 是 LoRA 初始化后的第一次更新**(LoRA 的 B 矩阵初始为零,梯度结构特殊),不具代表性。
**判别方法(先写后测)**:若后续 update 的 `B_noise` 上升并稳定在 ~500 量级,
则 upd=0 是初始化瞬态,按稳定段判读;若始终 ~112,则说明分解式还漏了一项共享结构,
**必须查清才可判读,不得直接用**。

## ⑧ 零成本修正设计(按 prompt 切半批)

由 §4.81 的结构性推论:**梯度累积是线性的,整批梯度与 microbatch 如何切分无关**。
⇒ 把 epoch 内的洗牌改成"前一半 microbatch 只含 prompt 0–23、后一半只含 24–47",
**`optimizer.step()` 看到的梯度逐 bit 不变**(除 fp16 累加顺序的末位差异),
但两个半批变成 **prompt 不相交**,`ḡ_A·ḡ_B` 于是无偏估计**总体**梯度 `‖G‖²`,
prompt 抽样噪声不再被误算成信号。

这是**改测量不改训练**的干预,与本项目其他探针同性质。
