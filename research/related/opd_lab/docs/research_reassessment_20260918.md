# 重新审视原始 idea、实现与下一步

2026-09-18。本次是原始讨论、源码和冻结结果的审计，包含一次 CPU 标签重算，不是新的训练结果。原 Phase20 标签、目标、检查点、主检验和已有汇报均未改写。重算脚本、输入 hash 与结果见 [审计目录](../experiments/local_expert_reassessment_20260918/README.md)。

**判断：外部专家的局部有效修正可以被学生学会，这一点已有小规模正例；但“终点验证筛选比认真训练普通 OPD 更有效”仍未成立。当前不能说方法已经 work，也不能把失败归结为一个已定位的代码 bug。比继续调学习率更优先的是：统一选择与评测的目标，确认相对固定教师的额外价值，再恢复持续刷新状态的训练。**

## 1. 原本要验证什么

原始两份讨论提出的是外部专家蒸馏，属于 OPD 路线。学生提供查询状态和后续轨迹，并不因此成为以自身奖励梯度构造目标的 OPSD。

一次迭代应为：冻结当前学生 b → 在 b 的轨迹上采集状态 → 专家提出动作 → 对各候选执行一次介入，用同一个 b 完成后续生成 → 按最终结果选择 → 用原 OPD loss 拟合少量步 → 刷新 b，重新采集和验证。

原方案还明确包含两个容易被遗漏的限定：

- “如果没有候选可靠地改善结果，就让 a*=a0。”因此拒绝状态拟合原学生动作本来就是一种设计选择，不能称为明显偏离初衷的实现错误。
- 决定是否继续，取决于相对**最佳固定教师、时间、幅度**是否有足够空间，以及学生是否能将其学成正常生成能力。只比未训练模型好，或只展示选中的正例，都不够。

固定 b 时验证出的局部收益，不等于更新后学生整条轨迹的收益。拟合会改变前缀状态、多个时间步和后缀；离散文字/数量成功也不随动作 MSE 平滑变化。这是原问题自身的困难，不是换一个 loss 名称就能绕过。

## 2. 哪些实现目前有证据支持

本次执行了 41 项定向 CPU 测试，全部通过；包含真实 tiny SD3/PEFT 合约检查，不是只有 mock。覆盖范围如下。

| 检查 | 结论与边界 |
|---|---|
| 确定性 OPD loss | `0.5 * mean((dt * (prediction - target.detach()))²)` 与固定上游源码抽取的 loss kernel 一致。只支持单教师、确定性 Euler 这一分支的对齐，不等于完整训练 recipe 或论文数值复现。 |
| 教师/学生/behavior | 训练参数归属、无教师梯度、behavior 冻结、加载学生而不刷新 behavior 的路径通过测试。 |
| 局部介入 | 分支从同一状态出发，使用真实 sigma 步长；后缀继续使用冻结 behavior。当前是无历史的 Euler，未据此认证 DPM 等有历史 solver 的分叉。 |
| 三臂比较 | 同起点，重置模型/Adam/scaler/RNG；状态顺序一致，随机筛选在每个 prompt 内匹配接受数量，保存动作拟合路径与既有 kernel 对齐。 |
| 数据/标签复算 | 本次从冻结观察重建比较结果，核对 target manifest、观察及 key hash；没有改标签来让新解释成立。 |

源码入口：[method.py](../python/opdlab/method.py)、[backends.py](../python/opdlab/backends.py)、[acceptance_learning.py](../python/opdlab/acceptance_learning.py)、[review_prospective.py](../scripts/review_prospective.py)、[review_acceptance_collection.py](../scripts/review_acceptance_collection.py)。

未发现足以解释 Phase20 全部失败的核心数值 bug；不应据此说“所有实现都正确”。例如 Phase20 的文本编码计数尾部断言确实曾出错，完整训练产物已经过独立核验恢复，见原 [RECOVERY.md](../experiments/local_expert_v20/RECOVERY.md)。另一个容易误读的地方是通用 config 仍含 `fixed_teacher=ocr`、两个 teachers；本阶段实际以保存的 plan/actions 为准，只拟合 GenEval 动作。未来运行应输出有效配置，避免读配置时误判算法。

## 3. 新发现：筛选标准与主要终点评测没有完全对齐

当前 `compare()` 只把 text/count/color/relation 的已知 false→true 算作修复；`full_visibility` 只用于防止变坏。`visual()` 的 complete_scene 却要求所有子句**以及完整可见性**均为 true。Phase20 rubric 第 26–30 行明确这么写了，所以代码遵循了旧协议；问题在协议目标不完全一致。

例如以下两例，原图文字和数量/颜色已正确，教师修复了裁切，当前规则却仍给 noop 目标：

| 冻结采集 case | 原图 | 教师结果 | 当前目标 |
|---|---|---|---|
| 2，count08 / seed926945309 | FRESH + 两杯正确，但杯底裁切 | 两个完整杯子，文字仍正确 | noop |
| 39，color11 / seed629774380 | PEACH + 绿色椅子正确，但椅脚裁切 | 椅脚完整，文字/颜色仍正确 | noop |

本次也查看了这四张原尺寸图，未追加或覆盖旧标签。全体原图仍见 [collection_cases.html](../experiments/local_expert_v20/collection_cases.html)。

使用同一份 48 状态冻结标签重算，结果如下。这里是**直接执行保存的候选动作并接冻结后缀**，不是训练后学生的分数。

| 策略 | 执行教师动作数 | 完整场景 | 已知损伤 |
|---|---:|---:|---:|
| 原学生 noop | 0/48 | 16/48 | 0/48 |
| 每个状态都用教师 | 48/48 | 25/48 | 4/48 |
| 原冻结筛选 | 9/48 | 24/48 | 0/48 |
| 事后将仅可见性修复也纳入 | 11/48 | 26/48 | 0/48 |

第四行是**事后规则敏感性分析**：未训练、未在独立数据评测、未经过新的独立人工确认，不能当成改进后的方法结果。全部数据来自 6 个熟悉的 prompt；4/48 的已知损伤只衡量已标注约束，不包括所有画质问题。

教师相对原图新增 13 个完整结果、损失 4 个。原筛选接受了其中 8 个新增完整结果，遗漏了 5 个：上面两个可见性修复，加上 case13/42/47 三个比较含 unknown 的情况。后三例不能直接变成“安全正例”，必须保留不确定性。

解释必须同时保留两面：当前筛选在完整成功数上没有超过直接教师，但从 16 提升到 24 且未产生已知损伤，可能具有**收益与损伤之间的取舍价值**。不能因 24<25 就否定所有筛选价值，也不能忽略它尚无完整成功数优势。即便事后纳入可见性，完整数也只比该固定教师多 1/48，尚不足以单凭这个数字支持昂贵的复杂筛选主张。

## 4. 最近的实现检验了原 idea 的哪一部分

Phase20 是固定查询的监督消融，并非完整的在线改进循环：

- 起点为 `runs/le7_fit_001/checkpoints/joint/step128.pt`。它来自 Phase7 的**五个刻意挑选正例的 joint fit**，是有效的机制诊断起点，不是充分训练过的通用 OPD baseline。
- 采集只覆盖 6 个正 prompt × 8 个 seed；另加 6 个保护状态。54 个状态反复拟合 128 次更新，没有在更新后重新采集状态、重新验证候选。
- 该轮候选只剩一个教师、一个时间 index3、幅度 1。可以隔离“是否接受该教师”的机制，但不能直接证明多专家互补或复杂动态路由的必要性。
- 通用 [engine.py](../python/opdlab/engine.py) 每个外层 epoch 已有刷新 behavior 的逻辑；最近使用的 `fit_saved()` 有意保持 behavior 和状态不变。需要恢复原流程，不必再建一套框架。
- Phase20 新 seed 的评测未额外查询教师，所以无法计算这些具体评测状态上“教师仍能修好而学生没学到”的比例。Phase19 的两例缺口是不同 seed，不能直接替代。

这组实验仍然有价值：它较干净地说明当前固定训练条件下 verified 未优于 random/all_teacher。但没有完整回答“更广分布上，持续验证并刷新目标的 OPD 能否改进”。反过来，改回在线也不是成功保证：必须先有可靠的评价器和充分的目标价值。

## 5. 保持损失是待验证原因，不是已定位根因

Phase20 筛选每组 1536 次反向查询中：144 次教师目标、624 次拒绝状态 noop、768 次独立保护 noop。保持目标占查询次数的 90.625%；这个比例**不是梯度贡献比例**。128 批中有 32 批没有教师目标，仍按原协议更新 Adam。

接受点相对 MSE 中位数：all_teacher 0.1772、verified 0.2450、random 0.9609。拒绝点预测漂移中位数：all_teacher 0.08750、verified 0.000822、random 0.000789。它们与“保持约束压制修正”相容，但不能排除监督覆盖、动作误差和跨状态泛化等解释。

另外，[Phase3](../experiments/local_expert_v3/STATUS.md) 已做过有/无拒绝保持项的较短拟合：去掉它没有得到稳定的普通生成优势。条件与 Phase20 不同，不能替代新消融；但这也提醒我们，不应把 mask 包装成还没检查过的必然解法。

因此修正此前的下一步建议：保留 `certified_masked` / `random_matched_masked` 作为一个小型机制消融，但不要再把它列为整个研究最重要的前提。如果执行，接受位、分母、状态、保护项等保持原协议，只变 mask；应明确 912 次反向查询与旧 1536 次不同。不能同时加入可见性新规则、在线刷新和新 LR，然后将变化归因于 mask。

## 6. 什么支持继续，什么不支持

支持可学习性：Phase7 五正例联合拟合中，4/5 的局部修复和 3/5 的完整生成修复保留；Phase10 的一个新鲜苹果关系修正也能进入普通生成。它们说明这条信息传递链并非天然不可能，但都是有意选择的训练例。

不支持稳定优势：Phase20 主要新 seed 单步完整数为初始 6/12、全部教师 9/12、筛选 6/12、随机 6/12；筛选完整路径虽为 8/12，全部教师同为 8/12，且全 32 单步仍有 2 次已知损伤。不能用后者替换失败的主检验。

用户人工复核也未确认筛选领先。在四臂都有完整分类回答的同 7 组中，确认成功为初始 4、全部教师 5、筛选 4、随机 5；初始和全部教师各有 1 个未决，不能把它们算作失败。总体只有 94/144 字段填写，剩余是缺失，不是负例；这些数字不支持显著性或总体排名。[人工复核分析](../experiments/local_expert_v20_human_review_v1/analysis_001/REPORT.md) 是测量边界的重要证据，并非没有价值。

当前 `quality_floor` / `quality_drop_tolerance` 均未启用；合成标牌任务又偏向严格文字与简单对象约束，因此“完整场景正确”仍不等于自然、美观、多样的图片。后续评价要将这些轴分开，不能为了得到好看结果事后放宽原严格指标。

## 7. 调整后的推进顺序

**第一步：先确定要证明的收益，独立核验候选价值。** 在新版本协议中统一候选接受和主评测的约束集合（包括完整可见性），明确 unknown 的处理；已知修复、比较不确定、已知损伤分开记录。若主要诉求是“不损害已有正确内容”，就同时报告完整成功和损伤曲线，比较同等损伤容忍度下的固定策略，而非只讲平均 reward。

用少量但更多样、与开发示例分离的 prompt 建立冻结候选诊断。固定策略的教师/时间/幅度先在开发集选定，再在独立集和选择策略比较；不能把测试集最佳组合称作已部署 baseline。重点是确认“选得好”相对“固定用强教师”有可重复的额外价值，且不是靠大量无法判定的标签支撑。自动 verifier 尚未得到独立确认时，可先用有限盲审测量机会，不必急着训练更复杂 verifier。

**第二步：价值成立后，恢复最简单的在线 OPD 训练。** 使用干净 backbone 或明确训练过的共同 OPD checkpoint。先有同起点、同数据的普通教师监督正向对照，再比较固定教师、密度匹配随机、终点验证三组。一次只改监督选择：冻结 behavior → 新鲜轨迹 → 验证 → 少量拟合 → 刷新。覆盖预定时间分布，持续评测普通完整生成；学习率、loss、EMA、CFG 等先保持一致。

这一步无需新 critic、shadow optimizer 或额外 reward-gradient loss。如果单步目标实测太脆弱，才比较按实际 sigma 定义的短区间介入；接受一个区间时监督该分支真实状态上的整段动作，不能只学第一步却按整段收益给标签。

**第三步：用可定位失败的三级检查推进。**

| 检查 | 失败时优先处理 |
|---|---|
| 冻结候选相对强固定策略有无可靠额外价值 | 候选/任务/接受标准；没有空间就停止复杂筛选主线 |
| 已接受训练目标能否兑现为实际终点改善 | 拟合残差、监督冲突、更新幅度；不能只看 MSE |
| 新 prompt/seed 的普通完整生成是否改善且控制损伤 | 新鲜状态覆盖、时间覆盖和泛化；不要继续只拟合旧查询 |

跨 sampler/steps 是再下一层目标。当前新方法连训练 sampler 上的稳定优势都未建立，不能直接套用旧 Q-core 的粗网格归因；刷新状态也不会自动保证换 sampler 有效。先在一个部署配置建立可靠收益，再预先规定不同步数/solver 的验证和必要的训练混合。

此前不断拆出下一轮小实验，对理解机制有帮助；但现在更应回到原始两个门槛：**选择有额外价值，以及该价值能变成学生的普通生成能力。** 后续阶段应围绕这两个门槛设停止条件，而不是默认再开一轮固定样本拟合。
