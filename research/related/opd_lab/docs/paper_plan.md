## 1. 要产出的论文

研究问题：**全局擅长某项能力的专家，在当前学生状态上给出的具体修正，是否真正改善最终图像？怎样把有益且保留正确内容的修正，学成一个学生的正常生成能力？**

主任务是同一张图同时满足文字、计数、颜色、关系等约束。主结果是联合成功率，同时检查五项通用质量。最终目标为一个学生正常采样，教师、候选分支和verifier均不参与部署。早期时间条件实现使用两份student adapter（发布anchor与learner）；Phase66已实际验证物理单adapter完整生成。两者是不同历史部署协议，不能混写。

本线属于外部专家的OPD蒸馏。Q表示固定behavior和采样协议下、通过实际介入终点测得的动作价值；第一版不学习Q critic，不使用OPSD式reward-gradient目标，不引入shadow optimizer。连续更新behavior、LoRA/MSE、分支采样和融合教师本身都不能单独充当新意。

拟争取的三条贡献及成立条件：

| ID | 主张 | 必须拿到的证据 | 当前状态 |
|---|---|---|---|
| C1 | 全局强专家存在有害/不合适的局部修正，按状态验证有实际价值 | 全样本净收益、损伤、可修复覆盖；优于开发集选定的最佳固定教师/时间/幅度/长度 | 有局部正反例；超过强固定策略的稳定空间未建立 |
| C2 | 被终点验证的动作能学成可泛化的学生能力 | 目标直接介入→拟合动作介入→新提示词完整生成，逐层测量；胜过匹配随机/固定监督 | Phase55筛选增量不确定；Phase59/60新验证57/52、随机53/50，池2未保住旧joint，接受修复8/12与5/10；质量仍低于起点，C2未成立 |
| C3 | 这种用专家和奖励的方式值得额外成本 | 同初始化、同信息、同总预算强对照；联合正确率/质量随GPU-hours曲线；部署无额外开销 | 尚缺完整比较 |

**C1、C2、C3都没有被当前结果完整证明。** “选择集合包含原动作，所以测得分数不下降”只是固定状态/后缀/评分器下的选择性质；它不是训练后模型、真实视觉正确性或跨采样器改进的保证。

当前查新已确认：[REST](https://arxiv.org/abs/2608.09226)用轨迹优势对蒸馏监督赋予正负权重；[ReNFT](https://arxiv.org/abs/2609.00061)已有匹配prompt/noise的反事实混合路线，再用NFT更新修复多样性。因此“奖励筛选蒸馏”“反事实分支”不能单独声称首次提出。需要证明的是**当前学生状态上、具体外部专家修正的终端增量、语义保持及其部署实现**，并加入廉价轨迹奖励加权蒸馏对照。这里基于论文摘要作初步区分，正式论文仍需全文方法/实验逐项比对。

## 3. 完整方法的最小实现

### 3.1 一轮流程

```mermaid
flowchart LR
    A[冻结本臂当前学生 b] --> B[在学生轨迹采状态]
    B --> C[原动作与少量专家修正]
    C --> D[同状态分支并接相同 b 后缀]
    D --> E[终点逐约束验证并选目标]
    E --> F[原OPD局部损失拟合少量步]
    F --> G[正常完整生成评测]
    F --> A
```

初版沿用SD3.5-M、LoRA、确定性Euler/Flow10。开发过程固定CFG、精度、EMA、优化器和数据；不同时调多个因素。早期协议采用发布Student LoRA作为共同OPD warm start；Phase66已经新增纯SD3.5-M＋共同fresh LoRA的四臂比较，全部新建optimizer，属于从底座短跑诊断。它尚非充分训练的论文主比较。未来若再用warm start，必须另行声明并保留同起点原生继续训练对照，不能与从底座结果混算。

目前S1仅保留为历史机制诊断。Phase45–46使用核验过的发布Student，Phase47–48沿各自训练历史继续；这不等于原版OPD训练复现。Phase66已落实共同初始化、新建optimizer和各臂在线采集；但原生只有单GenEval教师、64训练、16轮，仍缺强多教师基线及充分训练。不同历史checkpoint不可作为公平共同起点。

### 3.2 小候选集，最多两步

在状态s，原动作a0=v_b(s)。专家T提出

`a(T,alpha) = a0 + alpha * (v_T(s) - a0)`。

开发候选最多5条分支：原行为、OCR半幅/全幅、GenEval半幅/全幅。第一版不加入第三个质量专家、不学习路由网络。沿用已有早期两步窗口作为开发默认；用一个单步对照检验能否进一步缩短。正式窗口/幅度在开发集确定后冻结，不从确认集选择。

对于两步候选，第二步在该候选实际到达的状态上重新查询behavior和专家，不能复用另一个分支的动作。保存并监督**两步的状态—动作对**。端点验证对象是整个两步序列，不能把序列收益分别宣称为两步各自的因果收益。所有分支结束后由相同冻结b继续采样。

单步/两步如果都没有足够空间，先缩小或停止主张；不无限延长接管窗口直到变成完整教师生成。若GenEval不提供额外机会，首版保留单OCR专家，并把多专家扩展标记为未成立。

### 3.3 终点选择

每个候选保存逐项结果`true / false / unknown`、可选连续进展、独立运行错误和原始证据。运行错误与“图像语义无法可靠判定”必须分开；不能把unknown转换成false或true。缺检测框不能在解释中直接命名为物体真的消失。

原行为终点作为对照。优先选择：有可确认的约束修复，且原本已满足的语义要求没有确认损失、保护判断足够可靠的候选。候选效用使用预先固定的联合成功与分项进展；并列时选改动更小者。没有可信改善则选择原动作。所有条件、覆盖率、弃权和损伤均报告。

训练选择器与最终评测职责分离：保护的是提示词语义要求，不是所有像素或所有外观都不许变化。碗稍微升高、书转向、花瓶底座形状改变，只有破坏声明要求时才构成该项损伤；一般画质/自然度另行评价。当前“完整可见性”检测代理保留为单列诊断，不能无说明地把标准GenEval主指标变成“GenEval AND这个代理”。未知证据不会因为改名就恢复接受。

基础版本使用一个固定的、在开发集校准过的选择规则。CRAFT/多OCR投票、检测器阈值改动均是独立版本实验，不自动堆入主方法。所有奖励优化对照获得同一任务效用U；不能通过给本方法换更好的reward制造优势。

选择使用评价器A时，A上的被选收益只能算优化目标/内部诊断。确认集的关键净收益用未参与选择的固定评价器B及随机盲评复核，B不反过来改winner。A/B可能有共同误差，不能把它们一致叫真值。事后用评价标签挑出的oracle是机会诊断，不能充当可部署选择器或真实无噪声上界。

### 3.4 拟合和刷新

沿用确定性Euler分支的OPD transition-mean kernel：

`L = (1 / M) * sum_i m_i * 0.5 * mean((delta_sigma_i * (v_theta(s_i) - stopgrad(a_i*)))**2)`。

M是所有预定可能监督槽位数，包括拒绝槽位。Phase55主机制版本沿用masked训练：拒绝的查询没有专家梯度；整批无有效监督时跳过optimizer/EMA，避免momentum或weight decay造成无监督更新。按接受数归一化是另一算法配置，不能悄悄改变。该公式仅说明这个确定性分支，不等于全体上游随机OPD recipe。

**选择fallback与训练fallback分开命名。** 原始讨论的`a*=a0`确定候选选择行为；是否对拒绝状态拟合a0是独立设计。原始“全目标含noop”作为一个明确消融。全轨迹retention anchor另作可选消融，不默认保留λ=1，也不同时再加no-op和更多正则。Phase57已实现该全目标消融；两池部分结果中漂移受控而任务下降。当前没有证据支持把保持项称为必需创新，也不能因四项质量回升就修改joint主判定。

每轮拟合少量步后刷新本臂behavior，重新采状态、候选、终点评价；保留该臂optimizer/EMA状态。不跨round复用过期target或重置Adam。不使用“所有方法一直跟随verified学生轨迹”的捷径。

测三个层次：目标原样介入的收益；已学动作在相同冻结后缀下的收益；新提示词上新模型完整生成的收益。MSE下降不代替任一终点指标。部署只加载一个完整学生，固定时窗切换S1/新模型是另一个部署方法。

### 3.5 对现有工程的具体修改

| 模块 | 已有能力 | 下一次实现范围 |
|---|---|---|
| `method.py` / `verifiers.py` | 单步候选、OPD kernel、二元Verdict/invalid错误 | 引入版本化三态证据适配，错误与未知分离；保持native代码不变 |
| `short_correction.py` / `refreshed_learning.py` | 真正两步分支和保存监督 | 抽出可复用1/2步候选表示，复用已验证路径，不另建训练框架 |
| `engine.py` | 每outer epoch刷新behavior，optimizer/EMA/resume | 接统一候选序列与证据接口；各方法独立轨迹和连续状态 |

## 4. 论文需要评测的完整内容

| 内容 | 数据/指标 | 论文角色 |
|---|---|---|
| 单能力保留 | 原生GenEval各官方任务类别；原生OCR奖励及另列exact-match/字符错误率 | 避免用联合任务训练破坏原有能力；原native协议独立复现 |

| 通用质量/对齐 | DrawBench固定分布上的PickScore、CLIPScore、HPSv2.1、Aesthetic、ImageReward | 完整报告，不挑涨幅最大的一列替代主指标；标注尺度与文本截断 |
| 多样性 | 同prompt多seed的图像特征距离/重复率，配合质量 | 检查模式坍塌；不能将多样性分数当质量或单独以不匹配FID作结论 |
| 机制 | 有害建议比例/幅度、候选覆盖、比最佳固定策略的净收益、选择精度/召回/弃权、三层实现差距 | 回答C1/C2；不能只报告成功选中的案例 |
| 效率 | 总GPU-hours、学生/专家前向、suffix NFE、decode/verifier、backward、峰值内存；部署latency/NFE | 回答C3；包括失败与调参，区分已有专家的蒸馏成本和含专家训练的端到端成本 |
| 泛化/稳定性 | 新文字、新对象组合、新模板；≥3独立训练seed；Flow10/20/40与DPM2 10/20/40，统一CFG/分辨率并报实际NFE | 跨步数主张只能由矩阵实测支持；随后第二backbone验证适用范围 |
| 独立可信度 | 固定标准评价器、未供训练选择使用的本地独立评价器复核、少量随机盲评 | 评价器之间有共同误差；旧助手观察不升级成人类真值 |

建立固定train/dev/confirmation/final-test分工，拆开文字、对象组合和模板；不只更换seed。旧熟悉产品展示模板不能代表一般多约束生成。公开基准按原始定义保留；自定义联合prompt的GenEval检测分数不冒称原始benchmark总分。测试不调threshold、prompt重写、checkpoint或CFG。

未知保持单列，报告联合成功下界/可能上界和不利敏感性；同时单列真正系统运行失败。报告全样本分母和条件损伤分母。随机盲评先抽prompt再看结果，诊断选例与代表性样本分开；不要求用户逐图评完整训练集。默认0助手直接读图，禁止转发给远程视觉模型绕过限制。

Formal样本量要用历史配对方差估算精度/功效后冻结。几十prompt的pilot只用于判断机制和方差；不能预设它能确认5pp的差异。按prompt分簇、保留所有配对seed；多训练seed逐个报告并单独估计训练随机性。预先指定主要比较和多重比较处理。开发/确认集只允许预声明上限内的扩样，不因结果不理想无限补例。

## 5. 对照：每个对照排除一种替代解释

| 对照 | 排除什么 | 何时做 |
|---|---|---|
| 共同初始学生；各发布专家 | 初始能力、教师单能力/联合能力 | 先固定/评测 |
| 原版DiffusionOPD继续训练 | 额外训练本身；主算法基线 | 短程即加入；native与机制引擎分开标记 |
| 最佳固定专家/窗口/幅度/1–2步；单查询式监督 | 只需固定策略/稀疏监督 | 必需；只在dev选最佳 |
| 匹配随机筛选、预测差异筛选、全部教师目标 | 接受量、监督强度、简单启发式 | 随机/全部必需，差异筛选为紧凑消融 |
| 轨迹reward/advantage加权OPD | 只需对好轨迹多蒸馏，不需要逐动作终端介入 | 短程加入的廉价同reward对照；称机制移植，不冒称完整REST复现 |
| 原生在线NFT；OPD+NFT共同专家和reward信息对照 | 额外终端奖励信息或更多训练算力 | C1/C2初步通过后必需；先做原生NFT适配，再定义有限开发预算的组合规则 |
| 同候选赢家整图SFT | 收益来自搜索好图本身，而不是局部动作监督 | 同候选比较，不称为原生NFT |
| TreeGRPO | 通用分支搜索/细粒度credit assignment | 扩大阶段；移植同U的改动明确标记 |
| OPSD/ReFL | 共同可微奖励设定下的优化竞争力 | 辅助任务；原版OPSD不能直接优化OCR exact-match。surrogate另名并计成本 |

正式主表应加入经核对的DanceOPD公开算法对照；在实现和协议核对完成之前，只能称当前fixed/single_query为单查询机制控制。保留两种清楚的baseline记录：原作者数据/配置的native复现，以及为共同联合任务数据作显式适配的算法比较。后者即便loss未变也不等于“一模一样原论文recipe”；数据、路由和预算改动逐项记录。

两个公平性问题单独设计：

1. **机制匹配**：短程各臂共享同一冻结查询/候选池，控制loss/optimizer/曝光顺序；随机与verified匹配接受槽位数。它回答选择本身是否有用，不代表完整online训练。
2. **算法效率**：各算法从同一初始化开展自己的在线采样。固定策略/OPD无需为“配平”故意运行无用分支；允许其在相同GPU-hours多训练。随机数量只能按预先规定的训练阶段聚合统计匹配，不获得逐样本结果或test标签。不能把verified候选池输入NFT然后仍称标准在线NFT。

统一optimizer steps不能替代同算力；同算力也不替代同信息/同起点。所有调参和teacher预训练成本的计量边界必须清楚。

## 6. 下一步按一个实验包推进

**P0，结束当前结果表征。** 仅补齐Phase33全600图的GenEval/任务证据，合并已有Phase40质量指标，输出同一个模型比较表。属于C2证据补全。评分器保持固定；不再为了提高旧gate的通过率反复改OCR。该步完成不自动触发训练。

**P1，完成最小方法与接口。** 做三态/invalid适配、1/2步候选共用表示、独立在线round状态、统一评测与成本输出。契约测试通过后做一次有限GPU smoke。此步验证实现，不宣称新收益。

**P2，回答C1的有无。** 用共同OPD起点和较宽的联合任务分布做一次受预算限制的候选诊断。开发/确认各拟48提示词、每题2seed，四任务族均衡；这些是pilot规模，不是正式显著性样本量。在开发端固定窗口/长度及最强固定策略后再输出确认端。报告全部样本净收益与损伤，用独立评价复核。若动态选择不优于最佳固定策略且置信上界排除值得投入的效果，不扩大复杂选择；若区间仍宽，按事先样本上限补一次，不能判作已通过。

**P3，回答C2的能否兑现。** 相同起点做原版OPD继续训练、最佳固定、匹配随机、轨迹奖励加权、验证选择的短程比较。机制对照共享一轮冻结池；正式短程随后让各臂独立连续刷新，拟先3个round并保留optimizer状态。持续记录三层收益和新prompt完整生成。三个round是诊断预算，不是训练收敛或稳定性证据。若目标有收益而拟合动作没有，处理实现/可学性；若局部学会而正常生成没有，才单独测试刷新频率或一种保持方式。

**P4，回答C3并形成主表。** C1/C2有可信信号后，加入NFT、OPD+NFT和候选赢家SFT，进行同预算曲线、正式任务/质量测试、3个训练seed。再补TreeGRPO、采样器/步数矩阵、第二backbone和独立小规模盲评。

每份协议在运行前填写：claim_id、状态/目标版本、唯一变化、对照、主指标、预期可证伪结果、算力上限、样本/扩样规则、结果后决策。实用最小差异与允许损伤界由旧数据精度和成本估算后填入，未填不生成确认集；不把事后阈值写回旧协议。

## 7. 简洁优化的顺序

先减候选数、共享前缀/原行为终点、批量后缀、按内容和版本缓存评分。这些优化不改变选择结果时优先。降低验证频率需单独测，不默认其他样本盲目蒸馏。减少专家数/两步变一步需要检验候选机会是否保留。教师/时间/幅度分布在主机制比较中保持一致。

只有“同网格方法成立、跨网格收益消失”后，才研究多网格采集/不同冻结后缀验证；它是额外消融，不能提前声称robust。DPM等有历史solver的分叉必须包含完整solver历史；部署eval支持DPM不等于训练候选分叉已正确支持DPM。

每次只改变一个可解释因素。不因保持、critic、shadow update或多教师听起来合理就将其叠加到主方法。方法复杂度必须由增量证据支付。
