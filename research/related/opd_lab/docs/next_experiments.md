# 下一步实验计划：先验证局部专家修正，再验证能否学到

状态：2026-09-10 开始逐步实施；实时进展和证据见 [实验记录](../experiments/local_expert_v1/STATUS.md)。下面的数据规模、步数和训练预算是第一轮设计，尚未调优；不能当作作者论文配置或已验证的统计阈值。

## 当前起点

代码与 CPU 契约测试已通过。现在已补齐显式查询清单、同噪声早/中/晚介入、所有候选图像和哈希、教师轮换控制臂、按 prompt 聚类的诊断报告及隐藏身份的图片复核页。`data/joint_pilot_v1` 是新建的 64/32/64 train/validation/test 开发集；文本词表和模板分开，物体类别共享，不能冒充公开 benchmark。真实 GPU 验证进度由实验记录单独更新。

本轮主线继续使用外部 OCR/GenEval 专家，按学生状态进行 OPD。原版 OPD 的对应机制是沿学生轨迹查询任务教师并积累蒸馏损失，见[作者仓库说明](https://github.com/ali-vilab/DiffusionOPD)。我们提出的附加机制是局部介入的终点验证和逐项约束保护。

## A. 真实 GPU 冒烟测试和 verifier 检查

先完成下面几项小规模验证：

- 选择 4–8 个清楚、可判断的同图约束 prompts，覆盖 OCR+计数、OCR+颜色、OCR+关系；先使用两到三个约束。
- 运行 SD3.5-M、两个教师、flow 10 步、五个候选的前向/后缀/解码/打分链路。
- 保存候选图片、识别文字、每个约束的判断以及可用的检测诊断。加入已有约束被破坏、文字缺失、额外文字等负例，确认 scorer 不会把这些情况误记为成功。
- 对固定教师对照和 verified 各完成 1–2 个 outer epochs，检查学生更新、教师/behavior 冻结、raw/EMA 导出、checkpoint 加载和独立正常采样。
- 同时跑新拉取原版 OPD 的短训练/保存/评测检查；任何缩短预算或单卡 override 明确标为 smoke，不称为完整论文复现。

通过条件是工程路径正确、输出可解释、成本可测量。此阶段不要求 reward 明显上涨，也不靠 toy 正向结果预测真实效果。

2026-09-10 的两轮 GPU smoke 已跑通，但 verified 第一轮接受目标的拟合误差上升到约 3.38 倍。因此在扩大训练前增加一个相同 GPU/相同初始查询的一次更新检查，比较学习率 3e-4、1e-4、3e-5；所有候选图像、分数和选择必须完全匹配，才比较更新后的误差。该检查仅使用 4 条训练 prompts，不据此选择 held-out 最优模型，也不把拟合误差下降当成生成效果提高。

## B. 冻结模型的局部干预诊断

准备 64 个 development prompts，每个 2 个生成 seed。固定同一学生 checkpoint，在 flow 10 步轨迹的索引 1、4、7（零起点；同时记录实际 sigma）分别介入。

每个查询比较五个动作：noop、OCR alpha=0.5/1、GenEval alpha=0.5/1。同一 prompt/seed 的三个介入位置必须来自同一条冻结 behavior 轨迹。

- 共 64 × 2 × 3 = 384 个查询。
- 最多 384 × 5 = 1920 次候选终点评价。可缓存重复的 noop 终点，但应记录实际生成/打分次数。
- 在最初的子集测量真实耗时后再确定作业预算，不预先虚构 GPU-hours。

已实现：显式查询清单、跨时间步共享初始 seed、候选图片保存和基于查询 id 的完整性检查。时间位置含义必须按实际 sigma 解读，而非假定索引均匀对应连续时间。

诊断重点：

| 问题 | 应报告的证据 |
|---|---|
| 教师是否在部分状态有害？ | 各 teacher/alpha/时间位置的收益分布、负收益幅度、已满足约束破坏率 |
| 是否存在可用的好修正？ | 每个查询中合格候选的 headroom、接受覆盖率、各约束上的变化 |
| 是否需要动态选择？ | 固定 teacher/alpha/时间策略与逐状态选择的差异；固定策略只在 development/calibration 数据上确定 |
| Verifier 是否可信？ | 对接受、拒绝和接近 margin 的例子进行隐藏候选身份的独立复核，报告分歧 |
| 专家是否适合复合 prompts？ | 在子集上查看教师正常完整采样；单任务强不等于复合条件下每项都强 |

**不能以“selected_local_gain > 0”作为方法有效的证明。** 选择器正是用这个 verifier 选赢家，存在选择偏差；这最多说明该候选集合在该代理指标上有机会。独立图像复核和后续完整策略评价不可省略。

以下情况应先修改设计：候选几乎没有可信正收益、某个固定策略已覆盖大部分收益、或者接受样本主要是 verifier 误判。无需人为规定一个未经校准的 harm-rate 百分比才能继续。

## C. 小规模、受控的蒸馏训练

诊断通过后，准备独立的 train/validation/test 清单。诊断 prompts 可归入 development/train，但不能作为最终 held-out 证据；模板族、文字和对象组合的划分规则需预先记录。

第一轮对照包括：

1. 原 backbone：统一评测中的起点。
2. 同一局部引擎的无筛选教师监督：OCR/GenEval 分别固定的策略，以及不读终端分数的教师轮换策略。
3. 随机接受对照：接受率在 calibration 数据上匹配，不能在 test 上设置。
4. 预测差异筛选：阈值在 calibration 数据上确定。
5. 终点验证和约束保护的方法。

当前 fixed、round_robin、random、disagreement、verified 已实现。教师轮换依据全局 query ordinal，不读取候选奖励。这组控制臂必须使用相同初始 checkpoint、训练 prompts、loss、时间采样、候选集合和 optimizer。原版 MOPD 的三教师/分任务数据与默认新方法的两教师/同图约束数据不同，直接相减不能单独归因于筛选。

同时保留原版 OPD 的独立复现进度；它回答原实现是否复现，受控引擎回答选择机制是否有用。若之后用改造后的 OPD 跑同一训练集，准确标为匹配设置的 OPD 变体。

试跑建议先固定约 100 个 outer epochs，检查点每 10 个 outer epochs 保存。接受率会影响真实 optimizer updates，分别报告查询数、更新数、累计生成/验证成本和 GPU-hours。用于机制诊断的控制臂都计算候选终点不等于原版 OPD 的最优效率；最终效率比较必须加入无需支付这部分诊断费用的原始 baseline。

进入上述预算前先解决两个检查点：生成图上的 verifier 误判需要独立复核/校准；一次更新的目标拟合必须在合理步长下可稳定下降。当前实现的 GenEval 教师 CFG=1、behavior CFG=4.5；后续应增加只改变 backbone CFG 的控制，避免将 guidance 差异全部归因为专家知识。

必须分开追踪：目标拟合误差、拟合后的同状态局部介入收益、以及 held-out prompt 上完整学生采样的收益。前两项变好而第三项不变时，应分析局部拟合如何影响完整轨迹。

## D. 尽早测试步数/solver 泛化

小规模训练期间就保留下列评价矩阵，不等长训练结束：

| sampler | steps |
|---|---|
| flow | 10、20、40 |
| DPM2 | 10、20、40 |

每格都用同 prompts、初始噪声、CFG、精度和 adapter 类型，计算“训练后模型 − 该格原 backbone/匹配控制臂”的 paired delta。不同格的原始 reward 不能直接相减当作训练增益。

先按共享评价成本选择少量检查点；根据 validation 决定候选模型，再在保留 test 上确认。置信区间按 prompt 聚类，多个时间步或生成 seed 不当成独立训练重复；确认阶段另用多个独立训练 seed。

如果增益只在 flow 10 步出现，应将其视为网格依赖的证据，随后研究多网格/多后缀训练。当前的终点选择规则本身没有提供跨 sampler 稳定收益的保证。
