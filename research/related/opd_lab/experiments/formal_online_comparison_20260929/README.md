# 下一步正式比较：先固定数据和对照含义

状态：CPU设计，未提交、未预留GPU。Phase64只补在线闭环，本目录不自动扩预算。

研究问题是验证信息是否带来完整单学生的增量，而不是只比初始学生更高。
建议四臂：共同起点正常SOPD-GenEval续训、局部全部目标、分层同量随机、终点验证。
都采用同一个512train集合；局部三臂使用相同query身份/seed/time和相同原始Student。
正常SOPD保留原在线采样和多时间步监督，只做共同数据/起点适配，不冒称原论文数据复现。
它与局部三臂属于算法比较；仅verified−random属于同量机制比较，不能混称同算力。

当前CPU提案为局部每批64查询、4族×8模板每格2题、每8批完整遍历512一次，
两遍1024查询/最多16更新。不是GPU预算或冻结训练计划；接受率和总成本仍需检查。
旧模板均衡日程只保证8模板均衡，不保证每个族×模板≥2，因此会有单例分层。
单例层若接受1个，随机也只能取同一个；新提案每层2题只保证存在选择空间，
仍须报告实际可自由选择层数、两mask差异和监督比例，不能保证随机一定不同。

query_schedule_proposal.json只是可复算的CPU草案，不能直接喂现有严格runtime validator。
需要另加版本化排程与测试，现有运行中的Phase64和历史源码不受影响。

unknown和五质量全报。主比较verified−random，强比较verified−正常SOPD；全部目标
帮助区分“减少监督”与“验证信息”。不将共享128题或重复训练池当成新独立prompt。
