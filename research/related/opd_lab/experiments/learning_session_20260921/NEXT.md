# 下一步：把“学到修正”和“保持已有能力”分开检验

当前证据支持继续研究这个问题，但不支持宣称方法已成功。局部终点验证有作用；将验证过的动作拟合到共享权重后，增益可能消失。Phase31说明固定周围轨迹能减少部分已知损害，但这个干预没有提高完整场景数。

## 一个具体、可归因的下一轮设计草案

共同起点仍用固定 S1。教师、训练提示词、同一批噪声、接受掩码、学习率、局部回归目标与8次更新保持一致。增加一个保持项：让学生在训练集的 S1 行为轨迹上拟合冻结 S1 的动作，包括监督窗口之外的状态，以及窗口内被拒绝的状态。接受目标仍是在真实 OCR 分支状态上的教师动作。

比较四个设置：已有的验证筛选、随机等量；新增的验证筛选+保持、随机等量+保持。这样可以分别检查保持项和选择规则的作用。保持损失的系数及采样位置需要在新图生成前固定；不在已有36个开发案例上扫参数。新增锚点查询、反向传播和GPU时间全部计入。若要宣称计算效率，还需计算匹配的普通拟合对照；当前四组首先回答机制问题。

起始草案的候选池包括：每个训练对在窗口外固定动作索引1、7的锚点，拒绝对再加入索引3、4的 S1 状态锚点。两组各有460个候选锚点，使用相同哈希排序规则，每次更新确定性轮取20个，与20个蒸馏查询保持1:1；8次更新使用160个不同锚点。两项损失都除以全部240个查询槽位，lambda=1是单一预设值，不扫参数。两组新增训练各需320次反向查询，共640次；这只是预算估计，实际 GPU 时间须另行测量。

训练集限定、锚点资格与预算一致性的 CPU 计划生成器已经实现，实际名单见 [retention_design.json](retention_design.json)。所有锚点来自固定 S1 原始行为轨迹，目标 detached，行为模型不更新；不能拿 OCR 分支状态冒充 S1 锚点。正式训练还需实现同样的时间步加权保持损失，核对缓存状态与目标、一次优化器更新，以及保持系数为零时与原版拟合的回放。**这仍是未启动的设计：尚未实现保持项训练，也没有提交新作业或宣称有效。**

实现审计还应利用一个直接的预期：学生初始化为同一个 S1 时，保持损失应在数值精度内接近零，第一次更新应接近对应的无保持版本；后续更新才体现保持约束。若初始化就存在明显保持损失，先检查模型加载、缓存状态和预测精度，不把它当成方法现象。这个预期尚未进行 GPU 验证。

主要判据必须同时包含完整场景增益、已知损害和未知项；动作 MSE、修正方向投影与潜变量漂移作为诊断。不要因为局部损失下降而自动续训。

## 后续确认

冻结方法后，再在全新提示词和噪声上做同检查点配对评测，准备独立人类确认。最终保留测试继续封存。只有同 sampler 的增益可信后，才扩展不同步数/sampler；当前实验没有验证其鲁棒性。
