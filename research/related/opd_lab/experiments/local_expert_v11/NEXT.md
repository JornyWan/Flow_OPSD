# Next: prospective repair selection with explicit preservation

Phase11给出的答案是“有部分迁移，但有损伤”。继续以外部专家的局部修正为核心，
保持 DiffusionOPD 的拟合损失；当前不转向 self-distillation，不把单个苹果的
成功当作自动筛选机制已经成立。此文件是下一阶段设计，尚未执行或冻结成run。

## 先做一个前瞻训练集采集关卡

从共同 joint128 状态开始，不用本轮验证结果逐图选 sparse32/sparse320。
在现有64个训练提示词上，每个提示词预先固定一个新seed，按任务均衡排序，
覆盖全部提示词；排除旧拟合与phase11 seeds。先冻结全部查询、模型、预算、
候选网格和选择规则，再生成任何候选图。保留32个验证提示词做统一发展评测，
64个test继续留到方法与超参数冻结之后。

最小诊断网格可沿用已得到新苹果修正的 query index3、alpha1，包含 noop、OCR
专家、GenEval专家三种动作：64组、192个终点、128次专家动作查询。准备时核对
后端实际forward/后缀长度计数与成本，不能把终点数当成总算力。该固定网格只
检验这一位置/强度的适用性；不依据生成结果临时扩大候选集合。

每个候选使用同一冻结学生/behavior状态、共享前缀与后缀模型。保存动作、状态、
终点、逐子句分数、选择结果、查询耗时及全部拒绝案例。直接运行已有冻结选择器，
在读图之前固定其决定；之后对全部192图作模型/分数隐藏的独立顺序复核。
这轮人工标签用于审计，不反过来挑一批最漂亮的训练目标。

应回答：候选中是否存在真实修复；自动选择器接受的修复有多少是真的；它漏掉
了多少；是否损伤原正确文字、数量、关系或可见性。分别给 precision、覆盖率、
含拒答的召回率和原true→false/unknown，而不是只报告平均reward。

如果候选确有收益但选择器不可靠，先修选择器，并另建新seed确认集，不能复用
同一批审计图同时调规则与宣称验证通过。如果候选本身缺少收益，再单独考察
介入位置/强度或专家覆盖；这不是“多训练一些”可以回答的问题。

## 再做保留目标的学习对照

采集通过后，在共同初始化、共同候选池与预先固定预算下，做一个小规模、完整
可重放的学习对照。当前 engine 对 rejected query 默认给零训练权重，phase10
则对4个保留点给 unit-weight noop 目标；两者必须在配置和实验命名里明确区分。

第一轮保持teacher、alpha、time、loss、optimizer、EMA、batch和更新预算一致，
只考察目标是否接受及未接受状态是否用冻结behavior动作保护：

1. 已有自动验证选择器，拒绝状态显式回归noop目标。
2. 同一选择器，拒绝状态零权重，测量保留目标的作用。
3. 同候选、同接受数/拟合次数的随机筛选，并采用相同保留规则。
4. 仅根据历史发展数据预先指定的固定专家/位置/强度，同样计入查询与拟合成本。

这些是机制对照，不能替代原版 OPD baseline。进入方法效果比较时，还要从相同
joint128继续训练原版OPD，并将其明确称为“继续训练原版OPD”；从原backbone
启动的正式比较另列。比较 GPU-hours、学生/教师forward和反向查询，不仅是
optimizer steps。若筛选减少有效监督，必须记录密度，避免把减少更新当成新方法。

先冻结一个短的采集→拟合→普通完整生成检查周期；达到预定预算就汇总全部结果。
每轮更新后refresh behavior并重新采集，避免复用旧状态上的动作。新seed和全部
验证提示词采用统一checkpoint与相同噪声，不能根据单图成败切换模型。

预期是可检验的分支，不是承诺：显式保留可能降低回归，也可能稀释修正；若只
保住旧图却没有新增完整成功，方法尚未达到目标。只有多提示词/新seed上同时
出现修复、有限回归，才扩大预算并加入多个步数/sampler的固定checkpoint评测。
phase11的单网格结果不支持对 sampler 鲁棒性的任何结论。
