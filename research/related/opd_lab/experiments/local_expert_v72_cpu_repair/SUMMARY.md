# Phase72：质量评分接口失败与独立 CPU 修复

2026-10-05 核查真实 Slurm：1067893 FAILED 1:0，实际占用 1084 L40S 秒。该轮已预留的 4500 请求秒不退款；本次没有新增 GPU、重试、timer、生成、训练或任务重评。原实验目录和运行快照未修改。

## 问题和责任

新控制器的 endpoint 记录漏了 `word`。共享质量评分器 `token_audit` 需要它检查目标文字是否因 prompt 截断而丢失，因而在第一个质量指标写入前发生 `KeyError('word')`。这属于本次控制器的接口错误；不能把这个退出码解释为方法无效。

之前 21 项测试覆盖路由和合成统计，没有调用真实的质量 token audit；“合成报告集成通过”不等于完整 GPU 评分接口已经验收。这是测试覆盖遗漏。

## 已修复和仍待做的事

活跃代码用共享 `endpoint_row` 构造任务和质量记录，从冻结的唯一 OCR 约束写入 `word`；不从 prompt 猜测文字。准备阶段检查 OCR 必须是第一个约束，以保持与现有 TaskScorers 的目标读取规则一致。缺失、多目标、空目标和非字符串目标在生成前拒绝。

33 项 CPU 测试通过，新增 12 项覆盖三个真实 token audit 接口的保留/截断行为、原异常复现及非法目标提前拒绝。没有更换或修改质量模型、评分定义、任务标签或科学门槛。

[bundle](bundle/) 保存修复后的 320 条 endpoint 和 320 条原任务评分副本。每条只添加 `word`；源图像路径、摘要和所有原任务证据保留。它是补评分的输入准备，不是完成报告。源记录和失败状态仍保持不变。

下一步是独立、只读复用现有端点的五质量补评，见 [恢复协议草案](RECOVERY_PROTOCOL_DRAFT.md)。不能重跑 Phase72 worker、复用失败作业预算或把来源作业改成 COMPLETED。本次未提交恢复 GPU。
