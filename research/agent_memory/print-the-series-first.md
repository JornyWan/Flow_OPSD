**2026-09-01 一夜之内,同一类错误犯了三次** —— 都是"读了汇总量或单点就下结论,
没有先把原始序列打出来":

1. **§4.75**:只用 **epoch 1** 的 48 条记录判"AdamW 让梯度更分散",epoch 2 符号翻转 ⇒ 全文撤回;
2. **§4.87a**:看 `B-c 漂移: 前半=384 后半=548`(比 1.43)就说"B_noise 随训练上升"。
   打印序列后是 `6.9, 3.6, 3.9, 4.2, 4.5, 3.5, 3.1, 3.3, 5.1` —— **非单调**,
   斜率方向还相反;那个 1.43 是 epoch-0 离群值造成的 ⇒ 撤回;
3. **§4.89**:用 bnoisep 的 **epoch 0 单点**(B_noise=181)判"余弦法与半批法差 4 倍",
   而对照的余弦值来自 epoch 0–7。同区间重比只差 **1.4×** ⇒ 数值结论撤回。
   epoch 0 是 LoRA 初始化瞬态(B 矩阵初始为零),**本就不具代表性**。

**Why:** 汇总量(中位/前后半比/CI)会把离群点、瞬态、非单调结构全部抹平。
高维梯度量在训练早期普遍有初始化瞬态,单点几乎必然误导。
三次里**只要当场打印了序列,一眼就能看出问题** —— 成本是一行代码,代价是一整轮返工。

**How to apply:**
1. **任何汇总统计量落地前,先 `print` 逐点原始序列**(时刻 / n / 该点的值),
   哪怕只有 5 个点。分析脚本应默认同时输出序列与汇总,不给"只看汇总"的机会;
2. **跨来源比较必须口径对齐** —— 同 epoch 区间、同 seed、同硬件。
   拿"某来源的单点"比"另一来源的多点均值"是无效对照;
3. **默认排除 epoch 0 / 首次更新**,或至少单独标出:LoRA 的 B 矩阵初始为零,
   首步梯度结构特殊(实测 B_noise 首点 181 vs 稳定段 500~800);
4. 趋势一律走三判据:**置换 p<0.05 且 前后半同号 且 幅度比<3**
   (§4.88 就是靠这个在 n=14 上把 n=9 时正确撤回的趋势重新立住的)。

**2026-09-10 补(同一会话内又栽三次)**:这条我在**目标轴**上一直遵守,
但每换一个**新的量**就又只看单点 —— 剂量差(§4.465)、族间隙(§4.466)、
held-out aesthetic(§4.472)全部如此,三次都是单点结论被轨迹推翻。
`aesthetic` 尤其危险:所有臂都是「ep20 深谷 → 回升」的强非单调形状,
ep20 与 ep100 给出**完全相反**的族排序。
**规则扩展:任何新引入的量,第一次用就必须先打轨迹,不只是目标轴。**

**2026-09-10 再补(第五种同类错误)**:除了"只看单点",还有"**把单个窗口的变化当趋势**"。
把 `lr8x u200` 的一个 7-epoch 下行(−0.0076)记成"见顶",下一轮就被震荡推翻。
**修法:先标定该量的自然波动**。实测(5 臂 242 个窗口):平滑训练奖励的 7-epoch 变化
SD = 0.0091,高 lr 臂 0.0103–0.0109 ⇒ **超过 ±2SD(±0.018,高 lr 臂 ±0.021)才值得标注**。

**2026-09-11 补(排序口径)**:`ls -1 checkpoints/ | tail -1` 取"最新 ck"是**字典序**,
`checkpoint-90` 排在 `checkpoint-100/110` 之后 ⇒ ck≥100 后永远报 90。
两个方向都危险:制造假警报(以为停写),也会漏报(真停在 ck95 时仍报 90)。
同型错误:`sort -t: -k1,1n` 把 `2-08:53` 排在 `5:41:20` 前(天与小时混比)。
**How to apply:** 对编号/时长排序一律显式数值化 —— `ls -1v`,或 `sed 's/[^0-9]*//' | sort -n`;
时长先换算成秒再比。

**2026-09-11 补(两次短序列"一致"不是证据)**:一个观察在 n=14 时是 +0.26×MDE,n=31 时 +0.28,
我据此在 §4.566 写"n 加倍后仍在,不像噪声"。等 n=66 重算 ⇒ **掉到 +0.02×MDE,就是噪声**。
**Why:** n=14 与 n=31 的样本**高度重叠**(前者是后者的子集),两者"一致"是必然的,不含新信息。
**How to apply:** 判断某量是否稳定,要看**不重叠**的窗口(如前半 vs 后半),或直接等到接近满程;
不要把"嵌套子集给出相近的值"当作稳定性证据。

**2026-09-11 补(两点不能定趋势,第三次)**:ck20 +0.24 → ck50 −0.61×MDE,我写了"翻号并放大"
并线性外推 ck100 ≈ −2.0。**实测 ck100 = +0.30×MDE,符号转回来了** —— ck50 那点是涨落。
同型错误本会话三次:n=14 vs n=31 的"一致"(嵌套子集)、ck20 vs ck50 的斜率、以及更早的排队位次。
**How to apply:** **三点以下不写"增长/放大/翻号/收敛"这类趋势词**,只报各点的值与各自的 t。
两个点永远能连出一条直线,那不是证据。
